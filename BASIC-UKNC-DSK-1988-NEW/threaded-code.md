# Шитый код Бейсик-Вильнюс: синтез и выполнение

Документ описывает две стороны промежуточного представления программы:
как компилятор (`COMP.MAC`) **порождает** шитый код и как интерпретатор
(`JMIN.MAC`/`JMP.MAC`) его **выполняет**.

Данные в таблицах сверены с исходниками; там, где смысл не выяснен до
конца, это отмечено явно.


## Часть 1. Синтез (COMP.MAC)

### 1.1. Формат представления

Скомпилированная программа - плоский массив слов. Каждое слово - либо
**адрес подпрограммы-обработчика** (собственно "нить"), либо **встроенный
операнд**, который этот обработчик прочитает сам. Разделителей нет:
границы определяются только тем, сколько операндов читает конкретный
обработчик.

```
       +--------+--------+--------+--------+--------+     +--------+
код:   | ОПКОД1 | опранд | ОПКОД2 | ОПКОД3 | опранд | ... | ENDPRG |
       +--------+--------+--------+--------+--------+     +--------+
         адрес    данные   адрес    адрес    данные        терминатор
```

### 1.1.1. Чем заканчивается код

Явного маркера конца нет - код заканчивается **обычным опкодом, который
не возвращает управление в поток**, т.е. не делает `JMP @(R4)+`, а уходит
в монитор. Терминаторов три, по контексту:

| Терминатор | Когда ставится | Что делает |
|---|---|---|
| `ENDPRG` | дописывается в `ENDTXT`, если программа не кончается на `END`/`STOP` | закрыть файлы, снять точки останова (`SEPAP`), вывести номер последней строки, `JMP STAR` |
| `HALT` | опкод оператора `STOP` | сохранить `R4` в `SAVJMP` (для `CONT`), вывести "СТОП", в монитор |
| `STAR` | `STATM` (`MONIT.MAC`) - оператор прямого режима | сразу `JMP STAR` - вернуться в цикл "Ok" |

`ENDTXT` не дописывает `ENDPRG` вслепую: сначала проверяет последнее
записанное слово (`CMP -2(R1),#ENDPRG` / `CMP -2(R1),#HALT`) и добавляет
терминатор, только если программа не заканчивается на `END` или `STOP`.

Оператор прямого режима (`STATM`) компилируется во временную область сразу
за кодом программы и терминируется адресом `STAR` - поэтому по завершении
единственного оператора управление само возвращается в монитор.

### 1.2. Указатель записи кода R1

`R1` - указатель записи; каждая подпрограмма компиляции дописывает слова
через `MOV #ОПКОД,(R1)+`.

**R1 нигде не инициализируется явно.** Он приходит побочным эффектом
вызова `GRBCOL` (`MONIT.MAC`) в начале `LRUN`: та уплотняет текст программы
и на выходе оставляет `R1 = ENDCOD` (см. её метку `6$`). Это единственный
источник начального значения указателя кода.

Проверка переполнения - одна на оператор, в главном цикле `COMPIL`:
`CMP R1,LENT / BLOS COMPIL`, иначе ошибка "Memory full".

### 1.3. Главный цикл

| Шаг | Что делает |
|---|---|
| `RUN`/`LRUN` | закрыть файлы, найти стартовую строку, сбросить состояние (`CLRCOD`, цепочки `DATA`/`AUTOON`), `GRBCOL` (и получить `R1`) |
| обнуление | пройти таблицу строк, очистить служебное слово каждой записи - оно станет головой цепочки forward-ссылок |
| `COMPIL` | по одной строке: `NUMBER` = номер, `R3` -> текст, разрешить ожидающие ссылки на эту строку, затем `CALL @AOPSUB(R2)` по коду оператора |
| `ENDTXT` | дописать `ENDPRG`, перенести тексты `DATA` в код, разрешить цепочку `AUTOON` (`RESTORE` без номера), выровнять `ENDCOD`, `STRMEM`, запустить (`VYK2`) |

### 1.4. Разрешение ссылок вперёд

Ссылки `GOTO`/`GOSUB` на ещё не скомпилированную строку разрешаются
**цепочкой, продетой через сами незаполненные слоты операндов**:

- служебное слово записи строки в таблице = голова цепочки;
- каждый ожидающий слот операнда хранит адрес следующего ожидающего слота;
- заглушка в конце цепочки - `TOTO1` (`.WORD ENDPRG`);
- когда строка компилируется, цикл `COMPIL 1$` проходит цепочку и
  записывает во все слоты текущий адрес кода `R1`.

Направление ссылки различается в `TO 5$` сравнением `CMP 4(R4),NUMBER`:
назад (строка уже скомпилирована) - адрес известен, патчим сразу; вперёд -
включаем слот в цепочку.

## Часть 2. Выполнение (JMIN.MAC / JMP.MAC)

### 2.1. Запуск выполнения

`R4` - указатель текущей инструкции. Чтобы начать выполнение, достаточно
выставить `R4` на первое слово кода и сделать тот же `JMP @(R4)+`, которым
заканчивается любой обработчик. Отдельной "точки входа в интерпретатор" нет.

Общий вход - `VYKDYT`/`VYK1` (`MONIT.MAC`):

```
VYKDYT::CLR	SAVJMP
	MOV	#-1,LYGIS	; программа выполняется
	CALL	CUROFF
VYK1:	CLR	TMPSP		; список временных строк пуст
	JMP	@(R4)+		; войти в шитый код с адреса R4
```

Кто и чем заряжает `R4` перед входом:

| Откуда | `R4` = | Случай |
|---|---|---|
| `LRUN`/`ENDTXT` (`COMP.MAC`) | `@ADRHLT` | обычный `RUN` после компиляции |
| `STATM` (`MONIT.MAC`) | `ENDCOD` | оператор прямого режима (скомпилирован в scratch-область) |
| `CONT` (`MONIT.MAC`) | `ADRHLT` | продолжение после `STOP`/точки останова |
| `BREAK`/`HALT` | `SAVJMP` | возобновление прерванной программы |

### 2.1.1. `JSR R4,STAND` - шитый код в миниатюре

Тот же механизм используется внутри подпрограмм, чтобы выполнить готовую
цепочку вызовов. `STAND` (`FLOATS.MAC`) - это ровно две инструкции:

```
STAND::	TST	(SP)+		; выбросить адрес возврата, положенный JSR
	JMP	@(R4)+		; и начать выполнять цепочку за местом вызова
```

`JSR R4,STAND` кладёт на стек старый `R4` и оставляет в `R4` адрес слова
**сразу за инструкцией вызова** - то есть начало списка адресов
подпрограмм, выписанного прямо в коде. `STAND` выбрасывает ненужный адрес
возврата и запускает этот список как обычный шитый код. Пример из `TANG`
(`FLOATS.MAC`) - вычисление `tg(x) = sin(x)/cos(x)`:

```
	MOV	R4,SAVJMP	; свой R4 сохранить - его займёт цепочка
	JSR	R4,STAND
	.WORD	SING		; sin(x)
	.WORD	TAN1		; спрятать результат
	.WORD	KOS		; cos(x)
	.WORD	TAN3		; проверить на ноль
	.WORD	DVR		; разделить
	.WORD	TAN2		; завершение (восстановит R4 из SAVJMP)
```

Так же устроен `ANG` в `GRAFUK.MAC` (перевод угла `CIRCLE` в координаты
точки). Поскольку цепочка занимает `R4`, вызывающий обязан сохранить свой
`R4` в `SAVJMP`, а замыкающий элемент цепочки - восстановить его.

### 2.2. Диспетчер

Каждый обработчик заканчивается

```
	JMP	@(R4)+
```

- прочитать очередное слово (адрес следующего обработчика), продвинуть R4,
перейти. Централизованного цикла диспетчеризации нет: **каждый обработчик
сам является диспетчером**.

Встроенные операнды читаются тем же автоинкрементом `(R4)+` внутри
обработчика - поэтому к моменту финального `JMP @(R4)+` указатель уже
стоит на следующем опкоде.

### 2.3. Передача значений

Значения выражений передаются через **стек процессора**:

| Тип | Занимает на стеке |
|---|---|
| целое | 1 слово |
| вещественное | 2 слова |
| строка | 2 слова: длина + адрес |

Регистры между обработчиками не сохраняются; `SAVJMP` служит ячейкой для
`R4`, когда обработчику нужен R4 под другое (`$USR`, `ANG`, `STRSQU`).

### 2.4. Таблица: обработчики со встроенными операндами

Только те, кто читает операнды из потока кода; остальные - в 2.5.
Обозначения типов - те же, что в 2.5 (`i`/`f`/`s`).

Многие из них помимо операнда работают и со стеком - поэтому колонки
"со стека"/"на стек" здесь тоже есть.

| Обработчик | Файл | Операндов | Что читает из кода | Со стека | На стек |
|---|---|---|---|---|---|
| `JMP` | JMIN | 1 | адрес перехода (`MOV @R4,R4`) | - | - |
| `JSR` | JMIN | 1 | адрес перехода (после укладки кадра GOSUB) | - | - |
| `IFT` / `IFF` | JMIN | 1 | адрес перехода (передают управление в `JMP`) | i | - |
| `RTS` | JMIN | 1 | пропуск слова при возврате | - | - |
| `RTSTO` | JMIN | 1 | адрес перехода (`RETURN <номер>`) | - | - |
| `ONJMP` / `ONJSR` | JMIN | 1+N | число вариантов и слоты адресов строк | i | - |
| `DFN` | JMIN | 2 | адрес продолжения (в обход тела), адрес ячейки функции | - | - |
| `FNCALL` | JMIN | 2 | адрес ячейки функции, число аргументов | аргументы | - |
| `APAR` | JMIN | 1 | смещение параметра от `PFACT` | - | i (адрес) |
| `SPAR` / `IPAR` | JMIN | 1 | смещение параметра от `PFACT` | - | f / i (значение) |
| `SCONST` | JMIN | 1 | старшее слово вещественной константы | - | 1 слово |
| `ICONST` | JMIN | 1 | целая константа / младшее слово вещественной | - | 1 слово |
| `$CONST` | JMP | 2 | длина и адрес строковой константы | - | s |
| `SVAR` | JMIN | 1 | адрес ячейки переменной | - | f |
| `IVAR` | JMIN | 1 | адрес ячейки переменной | - | i |
| `$VAR` | JMP | 1 | адрес дескриптора строки | - | s |
| `SMOV` | JMIN | 1 | адрес ячейки-приёмника | f | - |
| `IMOV` | JMIN | 1 | адрес ячейки-приёмника | i | - |
| `$MOV` | JMP | 1 | адрес дескриптора-приёмника | s | - |
| `INDEX` | JMIN | 2 | адрес записи массива, число измерений | индексы | адрес элемента |
| `ARRAY` | JMIN | 2 | то же, для объявления `DIM` | границы | - |
| `FORINT` | JMIN | 2 | адрес счётчика и адрес продолжения цикла | нач., кон., шаг | - (в кадр `CIKL`) |
| `NXSKIP` | JMIN | 1 | адрес переменной из `NEXT` (0 - без переменной) | - | - |
| `NEXSNG` | JMIN | 1 | пропуск пары слов (вещественный счётчик) | - | - |
| `RESTV` | JMIN | 1 | адрес `DATA` (или 0 - ближайший) | - | - |
| `READV` | JMIN | 1 | адрес переменной-приёмника | - | - |
| `GET` | JMIN | 4 | приглашение, флаги, список переменных | s (приглашение) | - |
| `TOINT` | JMIN | 1 | пропуск слова при отсутствии преобразования | i (признак типа) | - |
| `$DEFUS` | JMP | 1 | слот, куда записать адрес USR-подпрограммы | i | - |
| `$USR` | JMP | 2 | номер USR-функции, доп. слово (не выяснено) | аргументы | результат |
| `ONTRG$` | JMP | 2+ | флаг установки и слоты сохранения старого вектора | i (вектор) | - |

Примечания к отдельным строкам:

- `SCONST`/`ICONST` кладут **по одному слову** каждый; вещественная
  константа - это пара `SCONST`+`ICONST` подряд (старшее слово, затем
  младшее), а не один опкод.
- `APAR` кладёт на стек **адрес** параметра (для передачи по ссылке),
  тогда как `SPAR`/`IPAR` - его **значение**.
- `FORINT` не оставляет значений на стеке: снятые начальное/конечное
  значения и шаг укладываются в кадр цикла (область `CIKL`).
- `INDEX` заменяет лежащие на стеке индексы вычисленным адресом элемента;
  дальше значение читает/пишет соответствующий `*XVAR`/`*XMOV`.
- `DFN` вообще не трогает стек: он лишь регистрирует адрес тела функции в
  ячейке переменной и перепрыгивает через тело по первому операнду.

### 2.5. Таблица: обработчики, работающие только через стек

Большинство опкодов операндов из потока не читают - берут аргументы со
стека и кладут туда же результат. Обозначения: `i` - целое (1 слово),
`f` - вещественное (2 слова), `s` - строка (2 слова: длина + адрес).

**Арифметика и логика целых** (`JMIN.MAC`)

| Опкод | Со стека | На стек | Примечание |
|---|---|---|---|
| `SUM` | i, i | i | сложение, при переполнении `TRAP 6` |
| `SKIRT` | i, i | i | вычитание |
| `IDIV` | i, i | i | целое деление, деление на 0 - ошибка |
| `MOD` | i, i | i | остаток (тот же код, что `IDIV`) |
| `INEG` | i | i | смена знака |
| `ISGN` | i | i | знак числа: -1/0/1 |
| `NOT` | i | i | побитовое НЕ |
| `OR`, `AND`, `XOR`, `IMP` | i, i | i | побитовые операции (`AND` - через Де Моргана) |
| `SAND` | i, i | i | логическое И |
| `NEG` | f | f | смена знака вещественного (переключением бита знака) |

**Сравнения**

| Опкод | Со стека | На стек | Примечание |
|---|---|---|---|
| `ICMP` | i, i | - | вычитание, результат только во флагах процессора |
| `SCMP` | f, f | - | сравнение вещественных, результат во флагах |
| `$CMP` | s, s | - | сравнение строк (побайтно), результат во флагах |
| `TRUE` / `FALSE` | - | i | положить -1 / 0 (результат сравнения) |

**Переменные и массивы**

| Опкод | Со стека | На стек | Примечание |
|---|---|---|---|
| `IXVAR`/`SXVAR`/`$XVAR` | индексы | значение | чтение элемента массива (адрес вычислен `INDEX`) |

### 2.6. Совмещённые механизмы

**Стек кадров.** `FOR` и `GOSUB` укладывают кадры в одну область, растущую
вниз к `ENDCOD` (`CIKL` - вершина, `LIMIT` - текущий кадр `GOSUB`).
Различаются только тем, какой опкод их потом снимет, поэтому `NXSKIP`
проходит мимо чужих кадров, отыскивая нужный цикл.

**Самомодификация кода.** `$DEFUS` записывает адрес прямо в свой же
операнд; `ONTRG$` пишет в поток кода машинную инструкцию `JSR PC,@#адрес`
(`004537`) и направляет на неё аппаратный вектор прерывания; `HCOR`
(`MONIT.MAC`) подменяет слово кода переходом на `STPEND` - так реализованы
точки останова `STEP`/`TRON`.

**Вызов цепочки подпрограмм.** `JSR R4,STAND` - см. 2.1.1.


## Что остаётся невыясненным

- Точная разрядность/формат отдельных операндов у `GET`, `ONJMP`/`ONJSR`,
  `FNCALL` - структура понятна, побайтная раскладка проверена не полностью.
- Второе слово-операнд `$USR` (`R3`).
- Смысл спецобработки `REM`/`'`/`DATA` в `SET1` (`MONIT.MAC`).
- Сквозное описание `PFACT`/`TYPE` в компиляции выражений.
