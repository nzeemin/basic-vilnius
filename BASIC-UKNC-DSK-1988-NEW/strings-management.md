# Строки в Бейсик-Вильнюс (УКНЦ): представление и управление памятью

Документ собирает всё, что относится к строкам: как они представлены в
памяти, как выделяется и освобождается место под них, как устроены
строковые функции и операции.

Данные сверены с исходниками (`JMP.MAC`, `JMIN.MAC`, `TRAP.MAC`,
`COMP.MAC`, `MONIT.MAC`, `DAT.MAC`); там, где смысл не выяснен до конца,
это отмечено явно.


## 1. Представление строк

Строка везде описывается парой **длина + адрес текста**. Сам текст -
просто последовательность байт, без терминатора. Длина - один байт
(максимум **255 символов**, см. проверку в `CONCAT`).

Форма дескриптора зависит от места хранения.

### 1.1. На стеке выражений (2 слова)

```
        +-----------------+
 SP  -> | длина (мл.байт) |   старший байт - СЛУЖЕБНЫЙ (связка TMPSP, см. 4)
        +-----------------+
2(SP)-> | адрес текста    |
        +-----------------+
```

Верхнее слово - длина, под ним адрес. Это подтверждается потребителями:
`LEN` (`MOV (SP)+,@SP` - кладёт снятое верхнее слово на место адреса и
возвращает его как результат) и `ASC` (сначала `TST (SP)+` снимает длину,
затем разыменовывает адрес).

Ключевая деталь: раз длина не превышает 255, **старший байт слова длины
свободен**, и система использует его как байт-связку списка временных
строк (см. раздел 4).

### 1.2. Простая строковая переменная (2 слова)

В таблице переменных - те же два слова: первое - длина, второе - адрес
(`$VAR` читает `@R1` как длину и `2(R1)` как адрес). Присваивание `$MOV`
перезаписывает оба слова целиком, как обычное двухсловное значение.

### 1.3. Элемент строкового массива (3 байта, упакованно)

Для массивов дескриптор ужат до трёх байт:

```
        +--------+--------+--------+
        | длина  | адр.мл | адр.ст |
        +--------+--------+--------+
```

`$XVAR` распаковывает это в стековую пару из двух слов, `$XMOV` -
запаковывает обратно (`MOVB` длины, затем младший и старший байты адреса
через `SWAB`). Экономия - 1 байт на элемент против стековой формы.

### 1.4. Строковый литерал

Текст литерала лежит **прямо в потоке шитого кода**; опкод `$CONST`
получает два встроенных операнда - адрес текста и длину - и кладёт их на
стек. Копия при этом не создаётся: пока литерал только читают, он
работает как строка, живущая в области кода, а не в пуле.


## 2. Область строк (пул)

Четыре переменные в `DAT.MAC` полностью описывают состояние пула:

| Переменная | Смысл |
|---|---|
| `STRREG` | начало области строк |
| `STRSIZ` | полный размер области |
| `FREBEG` | начало свободной части (граница выделения) |
| `FRELEN` | сколько байт свободно |

Область размещается **сразу за скомпилированным кодом** и растёт вверх,
навстречу таблице переменных (`LENT`). Размещение делает `STRMEM`
(`MONIT.MAC`):

```
STRMEM::MOV	ENDCOD,R1
	MOV	R1,FREBEG	; пул начинается сразу за кодом
	ADD	STRSIZ,R1
	MOV	STRSIZ,FRELEN
	CMP	R1,LENT
	BHI	MEMFUL		; упёрлись в таблицу переменных - нет памяти
	MOV	R1,ENDCOD	; код теперь "включает" пул
	MOV	FREBEG,STRREG
```

Размер по умолчанию - **200 байт** (`MOV #200.,STRSIZ` в `START`,
десятичное). Меняется оператором `CLEAR` (см. 6).


## 3. Выделение памяти: bump-аллокатор

Свободных списков нет. Выделение - простое сдвигание границы `FREBEG`
вверх. Единственная точка выделения - `TSTFRE`:

```
TSTFRE::SUB	2(SP),FRELEN	; хватает места?
	BGE	1$		; да =>
	CALL	STRSQU		; нет - СБОРКА МУСОРА
	SUB	2(SP),FRELEN	; хватает теперь?
	BMI	STRFUL		; нет - ошибка 14
1$:	MOV	FREBEG,4(SP)	; вернуть адрес блока
	ADD	2(SP),FREBEG	; сдвинуть границу
	RETURN
```

Важное следствие: **сборка мусора запускается только при исчерпании
памяти**, не по расписанию и не по счётчику мусора.

`VIETOS` - вариант того же для временных буферов (`OCT$`/`BIN$`/`HEX$`):
размер в `R5`, возвращает **конец** буфера (эти функции пишут цифры с
конца назад), и при нехватке памяти не выдаёт ошибку, а выделяет сколько
осталось.


## 4. Временные строки: список `TMPSP`

Промежуточные результаты (`A$+B$`, `MID$(...)`, `STR$(...)`) размещаются в
пуле, но не принадлежат ни одной переменной. Чтобы их можно было
отбрасывать, они связываются в односвязный список с головой в `TMPSP`.

**Связка хранится в свободном старшем байте слова длины** прямо в
стековом дескрипторе - отдельной памяти под список не нужно.

Указатель ужат в один байт: стек лежит ниже `STACK=1000`(окт.), поэтому
`SP/2` всегда помещается в байт. `NEWTMP` пакует так:

```
NEWTMP::MOVB	TMPSP+1,1(SP)	; старая голова -> старший байт длины
	MOV	SP,TMPSP
	ASR	TMPSP		; упаковать: SP/2
	SWAB	TMPSP		; переставить в старший байт
```

Операции над списком:

| Подпрограмма | Что делает |
|---|---|
| `NEWTMP` | зарегистрировать строку на вершине стека как временную |
| `CLRTMP` | снять с учёта одну строку (вызывается функциями, "потребившими" аргумент - `LEN`, `ASC`, `VAL`, `NEWSTR`, ...) |
| `CLRTSP` | очистить список целиком (перед присваиванием - `$MOV`, `MIDMOV`) |
| `RETFN` | подрезать список до границы кадра `DEF FN` при возврате из функции |

### 4.1. Замечание об `RETFN`

`NEWTMP` пакует указатель как `SP/2` (`ASR`), значит распаковка должна
быть `ASL`, а обратная упаковка - `ASR`. В `RETFN` (`JMIN.MAC`) они,
судя по всему, **переставлены местами**: `ASR` стоит на распаковке, `ASL`
на упаковке. При таком порядке `R3` после "распаковки" равен `SP/4`, и
обращение `1(R3)` на следующем витке читает не тот адрес. Похоже на
ошибку в исходнике; проверить выполнением возможности нет, поэтому
отмечено, но не исправлено.


## 5. Сборка мусора: `STRSQU`

Компактирующая сборка методом выбора - тот же приём, что `GRBCOL` для
текста программы (`MONIT.MAC`).

Каждый проход ищет среди **всех живых строк** ту, что лежит по
наименьшему ещё не обработанному адресу, переносит её вплотную к уже
уплотнённой части и повторяет, пока живых необработанных строк не
останется. Сложность квадратичная, но памяти на служебные структуры не
требует вовсе.

Кто перебирает живые строки:

| Подпрограмма | Роль |
|---|---|
| `FIND` | перебор записей таблицы переменных (`LENT`..`TABTOP`); 0/1/2-пропуск возврата: конец / строковый массив / скалярная строка |
| `SSQ1` | для строкового массива - вычислить конец блока 3-байтных дескрипторов |
| `SSQ2` | прочитать очередной упакованный дескриптор элемента, собрать адрес из двух байт |
| `PERK` | перенести строку на новое место и поправить адреса в списке `TMPSP`, попавшие в переносимый диапазон |

По окончании `FREBEG`/`FRELEN` пересчитываются на новую границу.

`$FRE(x$)` намеренно вызывает `STRSQU` перед возвратом `FRELEN` - чтобы
показать реально доступную, а не фрагментированную величину.


## 6. Изменение размера пула: `CLEAR` / `CLRMEM`

`CLRSTR`/`CLR` (оператор `CLEAR [размер]`) пересоздают область строк:

- новый размер проверяется на то, что пул поместится до таблицы
  переменных, иначе ошибка памяти;
- **все существующие строки теряются** - `FREBEG` просто сбрасывается на
  начало области;
- таблица переменных сдвигается на разницу размеров, а её содержимое
  обнуляется (`ОЧИСТКА ПЕРЕМЕННЫХ`), причём базовые адреса блоков
  дескрипторов строковых массивов поправляются на ту же разницу;
- стек кадров `FOR`/`GOSUB` сбрасывается (`LIMIT=CIKL=LENT`).

`CLRMEM` (установка `HIMEM`) делает то же самое плюс сдвигает таблицу
строк программы (`TABMOV`) и всегда возвращается в монитор.


## 7. Операции и функции над строками

### 7.1. Копирование и склейка

`NEWSTR` - создать **независимую копию** строки: выделить память
(`TSTFRE`) и скопировать байты. Компилятор вставляет `NEWSTR` при
присваивании (`COMP.MAC`, `LET`), когда правой части нужна собственная
память - иначе переменная указывала бы на чужой (временный или литеральный)
текст.

`CONCAT` - склейка `A$+B$` с оптимизацией: вторая строка **дописывается
прямо за первой**, если первая уже лежит на границе свободной области.
Тогда новая память не выделяется вовсе, а `FREBEG`/`FRELEN` сдвигаются на
дописанное:

```
	ADD	2(SP),R2	; R2 = адрес1 + длина1 - место сразу за первой строкой
	...
1$:	MOVB	(R1)+,(R2)+	; дописать вторую строку следом
3$:	SUB	FREBEG,R2	; насколько ушли за границу
	ADD	R2,FREBEG	; сдвинуть границу
	SUB	R2,FRELEN
```

Проверка длины результата (`BIT #177400` на итоговой длине) даёт ошибку
15 при переполнении за 255 символов.

### 7.2. Функции, возвращающие строку

| Функция | Опкод(ы) | Примечание |
|---|---|---|
| `CHR$(код)` | `CHR` | по `ASFINT` |
| `BIN$`/`OCT$`/`HEX$` | `BIN`/`OCT`/`HEX` | пишут цифры с конца буфера `VIETOS` назад |
| `STR$(число)` | `SSTR`/`ISTR` | по типу аргумента (`ASTR`) |
| `STRING$(n,...)` | `ALLSK`/`ALLSM` | повтор кода символа / первого символа строки |
| `MID$`/`LEFT$`/`RIGHT$` | `LMID` | общий разбор в `TRAP.MAC` |
| `INKEY$` | `INKEY` | неблокирующее чтение клавиатуры |

### 7.3. Функции, возвращающие число

| Функция | Опкод | Со стека / на стек |
|---|---|---|
| `LEN(s$)` | `LEN` | s -> i |
| `ASC(s$)` | `ASC` | s -> i |
| `VAL(s$)` | `VAL` | s -> i/f |
| `INSTR(...)` | `INSTR`/`INSTR2` | наивный поиск подстроки |
| `$FRE(s$)` | `$FRE` | s -> i (со сборкой мусора) |

### 7.4. Сравнение и присваивание

`$CMP` - побайтное сравнение двух строк, результат **во флагах
процессора** (как `ICMP`/`SCMP`); материализуют его отдельные опкоды
`TRUE`/`FALSE`.

`MIDMOV` - присваивание вида `LET MID$(a$,n[,m])=b$`: копирует
`min(длина_нового, m)` байт **на место** внутри существующей строки, не
меняя её длины и не выделяя памяти.


## 8. Сводка жизненного цикла строки

1. Значение появляется на стеке - из литерала (`$CONST`), переменной
   (`$VAR`/`$XVAR`) или как результат функции.
2. Если оно занимает память в пуле, `NEWTMP` вносит его в список
   временных (связка - в старшем байте слова длины).
3. Операции (`CONCAT`, функции) при необходимости выделяют память через
   `TSTFRE`; при нехватке автоматически запускается `STRSQU`.
4. Функции, потребившие аргумент, снимают его с учёта (`CLRTMP`).
5. Присваивание переменной снимает учёт целиком (`CLRTSP`) - значение
   становится "владением" переменной; при необходимости компилятор
   заранее вставил `NEWSTR`, чтобы память была собственной.
6. Возврат из `DEF FN` подрезает список до кадра вызова (`RETFN`).
7. Всё, на что после этого нет ссылок ни из таблицы переменных, ни из
   `TMPSP`, при следующей нехватке памяти будет затёрто сборкой мусора.


## Что остаётся невыясненным

- Перестановка `ASR`/`ASL` в `RETFN` (см. 4.1) - ошибка или недопонятый
  приём.
- Точный формат перехода `FIND` к записям `TMPSP` (метки `8$`/`9$`/`10$`)
  и случай `R2 < LENT` на входе.
- Поведение округления в `PERK` при совпадении адресов источника и
  приёмника проверено только структурно.
