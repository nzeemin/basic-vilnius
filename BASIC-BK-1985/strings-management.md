# Строки в Бейсик-Вильнюс (БК-0010): представление и управление памятью

Документ собирает всё, что относится к строкам: как они представлены в
памяти, как выделяется и освобождается место под них, как устроены
строковые функции и операции.

Данные сверены с исходниками (`JMP.MAC`, `TRAP.MAC`, `COMP.MAC`,
`MONIT.MAC`, `BK.MAC`); там, где смысл не выяснен до конца, это отмечено
явно. Выполнением ничего не проверялось.


## 1. Представление строк

Строка везде описывается парой **длина + адрес текста**. Сам текст -
просто последовательность байт, без терминатора. Длина - один байт
(максимум **255 символов**: `CONCAT` и ввод `INPUT` проверяют длину через
`BIT #177400`, при превышении ошибка 15).

Форма дескриптора зависит от места хранения.

### 1.1. На стеке выражений (2 слова)

```
        +-----------------+
 SP  -> | длина           |   старший байт 0
        +-----------------+
2(SP)-> | адрес текста    |
        +-----------------+
```

Верхнее слово - длина, под ним адрес. Это подтверждается потребителями:
`LEN` (`MOV (SP)+,@SP` - кладёт снятое верхнее слово на место адреса и
возвращает его как результат) и `ASC` (сначала `TST (SP)+` снимает длину
и при нулевой длине - ошибка 5, затем разыменовывает адрес).

### 1.2. Простая строковая переменная (2 слова)

В таблице переменных - те же два слова: первое - длина, второе - адрес.
Читает их `SVAR` (двухсловное чтение, общее для строки и числа одинарной
точности), присваивает `SMOV` (двухсловная пересылка, тоже общая). Это же
значит, что перед значением в записи таблицы стоит слово имени с битом 15
(признак строки; см. `files.md`/`README.md`).

### 1.3. Элемент строкового массива (3 байта, упакованно)

Для массивов дескриптор ужат до трёх байт:

```
        +--------+--------+--------+
        | длина  | адр.мл | адр.ст |
        +--------+--------+--------+
```

`$XVAR` распаковывает это в стековую пару из двух слов, `$XMOV` -
запаковывает обратно (`MOVB` длины, затем младший и старший байты адреса
через `SWAB`). Тот же формат пишет ввод (`G20` в `GET`) при вводе в
элемент массива. Размер элемента в записи массива - 3 байта; массив
с таким элементом перебирают при сборке мусора `SSQ1`/`SSQ2`.

### 1.4. Строковый литерал

Литерал компилируется (`T120`, `TRAP.MAC`) в опкод `SCONST` с двумя
встроенными операндами - адрес текста и длина. Адрес указывает **прямо в
текст программы** (область `TEXT`, где строки лежат как набраны), а в
прямом режиме - в буфер ввода `BUF`. Копия при этом не создаётся: пока
литерал только читают, он работает как строка, живущая вне пула. Тип
выражения для строки - `TYPE` со старшим байтом -1.

Так как текст программы перед каждым запуском уплотняется (`GRBCOL`), а
код компилируется заново, адреса литералов всегда свежие.

### 1.5. Строки в статических буферах

Часть функций возвращают строку, лежащую не в пуле, а в статическом
буфере: `CHR$` - в `INK+1` (1 байт), `INKEY$` - в `INK`, `BIN$`/`OCT$`/
`HEX$`/`STR$` - в `BUFOUT`. Поэтому перед присваиванием и склейкой такой
результат копируется в пул (`NEWSTR`).


## 2. Область строк (пул)

Четыре переменные в `BK.MAC` полностью описывают состояние пула:

| Переменная | Смысл |
|---|---|
| `STRREG` | начало области строк (0 - область ещё не отведена) |
| `STRSIZ` | полный размер области |
| `FREBEG` | начало свободной части (граница выделения) |
| `FRELEN` | сколько байт свободно |

Область размещается **сразу за скомпилированным кодом** и растёт вверх,
навстречу таблице переменных (`LENT`). Размещение делает `STRMEM`
(`MONIT.MAC`), которую вызывают `ENDTXT` (перед запуском программы) и
`STATM` (прямой оператор, если область ещё не отведена):

```
STRMEM:	MOV	ENDCOD,R1
	MOV	R1,FREBEG	; пул начинается сразу за кодом
	ADD	STRSIZ,R1
	MOV	STRSIZ,FRELEN
	CMP	R1,LENT
	BHI	MEMFUL		; упёрлись в таблицу переменных - нет памяти
	MOV	R1,ENDCOD	; код теперь "включает" пул
	MOV	FREBEG,STRREG
```

Размер по умолчанию - **200 байт** (`MOV #200.,STRSIZ` в `START`,
десятичное). Меняется оператором `CLEAR` (см. 6). `CLRCOD` (при `NEW`,
`CLEAR`, загрузке) обнуляет `STRREG`, и область отводится заново.


## 3. Выделение памяти: bump-аллокатор

Свободных списков нет. Выделение - простое сдвигание границы `FREBEG`
вверх. Единой точки выделения нет: каждый потребитель (`NEWSTR`,
`STRING$` - `ALLSK`/`ALLSM`, ввод `G20`) сам вычитает длину из `FRELEN`,
берёт адрес из `FREBEG` и сдвигает `FREBEG`; общая только проверка
`TSTFRE`:

```
TSTFRE:	CMP	R1,FRELEN	; R1 - запрашиваемая длина
;	BLOS	1$		; (закомментировано)
;	MOV	R1,-(SP)
;	CALL	STRSQU		; сборка мусора - вызов закомментирован
;	MOV	(SP)+,R1
;	CMP	R1,FRELEN
	BHI	2$		; не хватает - ошибка
1$:	RETURN
2$:	TRAP	14.		; нет места под строки
```

Важное следствие: **автоматического запуска сборки мусора при нехватке
памяти нет** - в исходнике вызов `STRSQU` из `TSTFRE` закомментирован, и
нехватка места сразу даёт ошибку 14. Сборка мусора запускается только
явно: опкодом `$SQUEE` (его вставляет компилятор, см. 4) и функцией
`$FRE`.

`OCT$`/`BIN$`/`HEX$` пул не используют: они пишут цифры с конца буфера
`BUFOUT` назад и возвращают адрес внутри него.


## 4. Временные строки: учёт при компиляции

Промежуточные результаты (`A$+B$`, `STRING$(...)`, результат `FN`)
размещаются в пуле, но не принадлежат ни одной переменной. Списка таких
строк во время выполнения **нет**: строка на стеке - просто пара (длина,
адрес), и ничто не отмечает, кому принадлежит память. Вместо этого
компилятор на этапе разбора выражения отслеживает, свежая ли ("только что
выделенная в конце пула") строка получилась, и расставляет копирования.

**Признак свежести.** `TRAP 115` (разбор строкового выражения,
`TRAP.MAC`) возвращает в `R4` счётчик `R2`: больше нуля, если результат -
свежая строка в конце пула. Увеличивают его (`INC R2`) результаты
`USR$`/`FN` и `STRING$`; склейка с копированием; уменьшает (`DEC R2`) -
`MID$` (результат указывает внутрь исходной строки, новой памяти нет).
Литерал, переменная, элемент массива, `CHR$`, `INKEY$`, `STR$`, `BIN$`,
`OCT$`, `HEX$` счётчик не увеличивают.

**Флаг `TMP`** (`BK.MAC`, переменная компилятора, не значение времени
выполнения) - "в этом операторе `$SQUEE` уже вставлен". Он обнуляется в
начале компиляции оператора (`CLR TMP` в `COMPIL`, `STATM`, начале
`PRINT`), вокруг вложенного разбора строки `TRAP.MAC` его сохраняет и
восстанавливает.

**`TSTSQZ`** (`COMP.MAC`) вставляет в код `$SQUEE` (один раз на оператор:
`TST TMP / INC TMP`) и затем всегда `NEWSTR`:

```
TSTSQZ::TST	TMP
	BNE	1$
	MOV	#$SQUEE,(R1)+	; сборка мусора - один раз на оператор
	INC	TMP
1$:	MOV	#NEWSTR,(R1)+	; копия строки в пул
	RETURN
```

Её вызывают:

| Где | Когда |
|---|---|
| `S10` в `T115` (склейка `+`) | после первого слагаемого, если оно не свежее (переменная, литерал, статический буфер); так первое слагаемое становится последним блоком пула |
| то же, после второго слагаемого | `NEWSTR` без `$SQUEE`, если и оно не свежее - чтобы оказалось сразу за первым |
| `LET` | присваивание строки, если правая часть не свежая: копия в пул, чтобы переменная не указывала на литерал, статический буфер или чужую строку |
| `DEF FN` | напрямую `NEWSTR` (без `TSTSQZ`), если результат строковой функции не свежий; `TMP` увеличивается, чтобы `$SQUEE` в теле не вставлялся |
| `STRING$` | перед вторым аргументом: вставляется `$SQUEE`, а `NEWSTR` тут же стирается (`TST -(R1)`) |
| `READ`/`INPUT` | `$SQUEE` пишется первым словом оператора (`READ::`, `INPUT::`) |

**Следствия.**

- Сборка мусора в момент `$SQUEE` не просматривает стек выражений: на
  нём в этот момент могут лежать дескрипторы уже вычисленных частей
  выражения (например, первого слагаемого при `+`, или правой части
  присваивания). Что именно гарантирует их сохранность, из кода не
  видно (см. "Что остаётся невыясненным").
- Присваивание строки всегда копирует (если правая часть не свежая), а
  значит у каждой живой строки в пуле один владелец; на это рассчитан
  алгоритм сборки мусора (см. 5).
- Результат `MID$` и подстроки указывают внутрь исходных строк и
  отдельной памяти не занимают.


## 5. Сборка мусора: `STRSQU`

Компактирующая сборка методом выбора - тот же приём, что `GRBCOL` для
текста программы (`MONIT.MAC`).

Каждый проход ищет среди **всех живых строк** пула ту, что лежит по
наименьшему ещё не обработанному адресу (не ниже `R3` - начала
неуплотнённой части), переносит её вплотную к уже уплотнённой части
(`R3`) и повторяет, пока таких строк не останется. Сложность квадратичная,
но памяти на служебные структуры не требует вовсе.

```
R3 = STRREG                  ; куда класть следующую строку
конец = STRREG + STRSIZ
повторять:
    R0 = конец
    для всех записей таблицы переменных (FIND):
        строковая переменная:  если длина <> 0 и R3 <= адрес < R0:  R0 = адрес
        строковый массив:      то же по всем 3-байтовым дескрипторам
    если R0 = конец: выйти
    найти запись с адресом R0 и перенести: адрес := R3,
        переместить длину байт с R0 на R3 (PERK), R3 += длина
FREBEG = R3;  FRELEN = конец - R3
```

Кто перебирает живые строки:

| Подпрограмма | Роль |
|---|---|
| `FIND` | перебор записей таблицы переменных (`LENT`..`TABTOP`); возврат с 0/1/2-пропуском: не строка / строковый массив / строковая переменная |
| `MASREG` | размер массива в байтах без размеров измерений: размер элемента, умноженный на размеры всех измерений (`DAUG`), округлённый до чётного |
| `SSQ1` | для строкового массива - начало и конец блока 3-байтных дескрипторов |
| `SSQ2` | прочитать очередной упакованный дескриптор, собрать адрес из двух байт (0 для пустой строки) |
| `PERK` | перенести строку на новое место; если адреса совпадают, только сдвинуть `R3` |

Особенности:

- Переносятся только строки из пула. Литералы (в тексте программы), буфер
  ввода, `INK` и `BUFOUT` лежат вне области `STRREG`..`STRREG+STRSIZ` и
  условием `R3 <= адрес < R0` исключаются.
- Строки нулевой длины игнорируются.
- Алгоритм предполагает, что у каждой живой строки ровно один
  дескриптор: после переноса первой найденной переменной вторая, указывающая
  на тот же текст, осталась бы со старым адресом. Поэтому присваивание
  копирует строку (`NEWSTR`).
- Временные значения на стеке сборка не учитывает (см. 4).

`$FRE(x$)` намеренно вызывает `STRSQU` перед возвратом `FRELEN` - чтобы
показать реально доступную, а не фрагментированную величину.


## 6. Изменение размера пула: `CLEAR` / `CLRMEM`

`CLEAR` компилируется (`COMP.MAC`) в `CLR` (без аргументов), `CLRSTR` (один
аргумент - размер строк) или `CLRMEM` (два аргумента - ещё и `HIMEM`; если
первый пропущен, подставляется текущий `STRSIZ`).

`CLRSTR`/`CLR` (оператор `CLEAR [размер]`) пересоздают область строк:

- новый размер округляется до чётного и проверяется на то, что пул
  поместится до таблицы переменных (`ENDCOD` + изменение размера не больше
  `LENT`), иначе ошибка 7;
- **все существующие строки теряются** - `FREBEG` просто сбрасывается на
  начало области (`STRREG`), `FRELEN = STRSIZ`;
- массивы сдвигаются на разницу размеров вместе с областью;
- таблица переменных обнуляется (`ОЧИСТКА ПЕРЕМЕННЫХ`): значения
  скалярных переменных и элементов массивов - нули, базовые адреса блоков
  данных массивов поправляются на ту же разницу;
- стек кадров `FOR`/`GOSUB` сбрасывается (`LIMIT=CIKL=LENT`);
- если выполнение было в программе, оно продолжается (`R4` в коде), иначе
  в монитор.

`CLRMEM` (установка `HIMEM`) делает то же самое плюс закрывает файлы
(`CLOALL`), сдвигает таблицу строк программы (`TABMOV`), пересоздаёт буфер
файла (`CLRBUF`) и сбрасывает указатели кода (`CLRCOD`), после чего всегда
возвращается в монитор. Адрес `HIMEM` выше `70000` (окт.) - ошибка 5.


## 7. Операции и функции над строками

### 7.1. Копирование и склейка

`NEWSTR` - создать **независимую копию** строки: проверить место
(`TSTFRE`), выделить блок в конце пула и скопировать байты. Адрес в
дескрипторе на стеке заменяется на новый. Компилятор вставляет `NEWSTR`
при присваивании, перед склейкой и в `DEF FN` (см. 4).

`CONCAT` - склейка `A$+B$`. Вторая строка **дописывается прямо за
первой**, без проверки, где лежит первая: компилятор гарантирует это
копированием первого слагаемого в конец пула и тем, что второе слагаемое
свежее или скопировано сразу за ним. Тогда `FREBEG`/`FRELEN` сдвигаются
только на то, что действительно ещё не занято:

```
CONCAT::MOV	(SP)+,R0	; длина второй
	MOV	(SP)+,R1	; адрес второй
	MOV	@SP,R2		; длина первой
	ADD	R0,@SP		; итоговая длина = длина1 + длина2
	BIT	#177400,@SP	; > 255 ?
	BNE	2$		; да - ошибка 15
	ADD	2(SP),R2	; R2 = адрес1 + длина1 - место сразу за первой
	TST	R0
	BEQ	3$
1$:	MOVB	(R1)+,(R2)+	; дописать вторую следом
	SOB	R0,1$
3$:	SUB	FREBEG,R2	; насколько ушли за границу
	ADD	R2,FREBEG	; сдвинуть границу
	SUB	R2,FRELEN
```

Если вторая строка перед этим была скопирована `NEWSTR` в конец пула,
она уже лежит на месте, куда её дописывает `CONCAT`, и смещение границы
получается нулевым.

### 7.2. Функции, возвращающие строку

| Функция | Опкод(ы) | Где результат |
|---|---|---|
| `CHR$(код)` | `CHR` | `INK+1`, длина 1; код больше 255 - ошибка 5 |
| `BIN$`/`OCT$`/`HEX$` | `BIN`/`OCT`/`HEX` | `BUFOUT`: цифры с конца назад |
| `STR$(число)` | `ISTR`/`DSTR`/`SSTR` по типу (`ASTR`) | `BUFOUT` (`ISGUNP` для целого, `EGO`/`DGO` для вещественных) |
| `STRING$(n,...)` | `ALLSK`/`ALLSM` | новая строка в пуле; повтор кода символа / первого символа строки; `n` > 255 или пустая строка - ошибка 5 |
| `MID$` (выражение) | `STR`/`STR2` | указывает внутрь исходной строки (позиция 1-based, длина обрезается до остатка) |
| `INKEY$` | `INKEY` | `INK`, длина 0 или 1 |
| `USR$`, `FN` со строковым результатом | `$USR`, `FNCALL` | результат, при необходимости копируется `NEWSTR` |

### 7.3. Функции, возвращающие число

| Функция | Опкод | Со стека / на стек |
|---|---|---|
| `LEN(s$)` | `LEN` | s -> i |
| `ASC(s$)` | `ASC` | s -> i (пустая строка - ошибка 5) |
| `VAL(s$)` | `VAL` | s -> d (через `PACK`) |
| `$FRE(s$)` | `$FRE` | s -> i (со сборкой мусора) |

`INSTR` в исходниках есть, но под ложным условием и в сборку не входит.

### 7.4. Сравнение и присваивание

`$CMP` - побайтное сравнение двух строк (по длине общей части, затем по
разности длин), результат **во флагах процессора** (как `ICMP`/`SCMP`/
`DCMP`); материализуют его опкоды `EQ`/`NE`/`LT`/`GT`/`LE`/`GE`
(таблица `ADDRBR`), кладущие на стек -1 или 0.

`MIDMOV` - присваивание вида `LET MID$(a$,n[,m])=b$`: копирует
`min(длина_нового, m)` байт **на место** внутри существующей строки, не
меняя её длины и не выделяя памяти.

`PRINT` строки: `LIT` снимает длину (при нулевой снимает и адрес) и
выводит текст через `ISVETO`; память не освобождается.


## 8. Сводка жизненного цикла строки

1. Значение появляется на стеке - из литерала (`SCONST`), переменной
   (`SVAR`/`$XVAR`) или как результат функции.
2. Если оно оказывается не в пуле (литерал, буфер ввода, `INK`, `BUFOUT`),
   компилятор перед присваиванием или склейкой вставляет `NEWSTR`, и строка
   копируется в конец пула (`TSTFRE` проверяет место).
3. Результат склейки и функций типа `STRING$` лежит в пуле, но не
   принадлежит переменной; отметки об этом в памяти нет - есть только
   признак свежести на этапе компиляции.
4. Присваивание переменной просто записывает дескриптор: с этого момента
   строка - собственность переменной.
5. Всё, на что после этого нет ссылок из таблицы переменных, при
   следующей сборке мусора (`$SQUEE`, `$FRE`) будет затёрто. Автоматически
   при нехватке места сборка не запускается - вместо неё ошибка 14.
6. Повтор `INPUT` после ошибки 13 в исходниках 1985 года возвращается к
   самому `GET`; в ПЗУ 1986.07.24 повтор начинается на слово раньше - с
   `$SQUEE` (`JMP @-4(R4)` вместо `JMP @-2(R4)` после `G4:`), и строки,
   скопированные в пул при неудачной попытке, убираются сборкой мусора.


## Что остаётся невыясненным

- Как защищены от переноса при `$SQUEE` дескрипторы строк, лежащие на стеке
  выражений (см. 4): сборка мусора стек не просматривает. Возможно, это
  скрытая ошибка исходников, возможно, расстановка `NEWSTR` исключает
  опасный случай; из кода однозначно не видно.
- Условие "свежести" `R2`/`R4` у `TRAP 115`: смысл увеличений и уменьшений
  понятен для `USR$`/`FN`, `STRING$`, `MID$`, но для остальных ветвей
  (`SIMUSR`, значения `R4` в `LET`) проверен только в общих чертах.
- Роль условия `TST R4 / BGT` перед `NEWSTR` во втором слагаемом склейки
  (когда `NEWSTR` не нужен).
- Поведение `PERK` при совпадении адресов проверено только структурно.
- Что произойдёт при переносе строки, которая одновременно является
  значением двух дескрипторов (случаи не-копирующих присваиваний).
