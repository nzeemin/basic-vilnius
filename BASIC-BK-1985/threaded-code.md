# Шитый код Бейсик-Вильнюс для БК-0010: синтез и выполнение

Документ описывает две стороны промежуточного представления программы:
как компилятор (`COMP.MAC`, при участии `TRAP.MAC` и `MONIT.MAC`)
**порождает** шитый код и как интерпретатор (`JMP.MAC`, `FLOAT.MAC`,
`GRAF.MAC`, `BK.MAC`) его **выполняет**.

Данные в таблицах составлены по исходникам; там, где смысл не выяснен до
конца, это отмечено явно. Операнды обработчиков и действие на стек выведены
из кода, выполнением не проверялись.


## Часть 1. Синтез

### 1.1. Формат представления

Скомпилированная программа - плоский массив слов. Каждое слово - либо
**адрес подпрограммы-обработчика** (собственно "нить"), либо **встроенный
операнд**, который этот обработчик прочитает сам. Разделителей нет:
границы определяются только тем, сколько операндов читает конкретный
обработчик.

```
       +--------+--------+--------+--------+--------+     +--------+
код:   | ОПКОД1 | опранд | ОПКОД2 | ОПКОД3 | опранд | ... | ENDPRG |
       +--------+--------+--------+--------+--------+     +--------+
         адрес    данные   адрес    адрес    данные        терминатор
```

### 1.1.1. Чем заканчивается код

Явного маркера конца нет - код заканчивается **обычным опкодом, который
не возвращает управление в поток**, т.е. не делает `JMP @(R4)+`, а уходит
в монитор. Терминаторов три, по контексту:

| Терминатор | Когда ставится | Что делает |
|---|---|---|
| `ENDPRG` | дописывается в `ENDTXT`, если программа не кончается на `END`/`STOP`; опкод оператора `END` | закрыть файлы (`CLOALL`), снять точки останова (`SEPAP`), вывести номер строки, `JMP STAR` |
| `HALT` | опкод оператора `STOP` | сохранить `R4` в `SAVJMP` (для `CONT`), вывести "СТОП", в монитор |
| `STAR` | `STATM` (`MONIT.MAC`) - оператор прямого режима | сразу `JMP STAR` - вернуться в цикл "Ok" |

`ENDTXT` не дописывает `ENDPRG` вслепую: сначала проверяет последнее
записанное слово (`CMP -2(R1),#ENDPRG` / `CMP -2(R1),#HALT`) и добавляет
терминатор, только если программа не заканчивается на `END` или `STOP`.

Оператор прямого режима (`STATM`) компилируется во временную область сразу
за кодом программы и терминируется адресом `STAR` - поэтому по завершении
единственного оператора управление само возвращается в монитор.

### 1.2. Указатель записи кода R1

`R1` - указатель записи; каждая подпрограмма компиляции дописывает слова
через `MOV #ОПКОД,(R1)+`.

**R1 нигде не инициализируется явно.** Он приходит побочным эффектом
вызова `GRBCOL` (`MONIT.MAC`) в начале `LRUN`: та уплотняет текст программы
и на выходе оставляет `R1 = ENDCOD`. Это единственный источник начального
значения указателя кода.

Проверка переполнения - одна на оператор, в главном цикле `COMPIL`:
`CMP R1,LENT / BLOS COMPIL`, иначе `MEMORY` и ошибка 7 (`TXTSV`).

### 1.3. Главный цикл

| Шаг | Что делает |
|---|---|
| `RUN`/`LRUN` | закрыть файлы, найти стартовую строку, сбросить состояние (`ERRS`, `LYGIS`, цепочки `DATA`/`AUTOON`, стек кадров), `GRBCOL` (и получить `R1`) |
| обнуление | пройти таблицу строк, очистить служебное слово каждой записи - оно станет головой цепочки forward-ссылок |
| `COMPIL` | по одной строке: `NUMBER` = номер, `R3` -> текст, разрешить ожидающие ссылки на эту строку, затем `CALL @AOPSUB(R2)` по коду оператора (первый байт строки) |
| `ENDTXT` | дописать `ENDPRG`, перенести тексты `DATA` в код, разрешить цепочку `AUTOON` (`RESTORE` без номера), выровнять `ENDCOD`, `STRMEM` (отвести область строк), запустить (`VYK2`) |

Подпрограммы компиляции разбирают текст оператора через `TRAP 100`-`TRAP 130`
(`TRAP.MAC`): выражение (`T100`), имя и ссылка на переменную (`T105`, `T103`),
номер строки (`T110`/`T111`), ключевое слово (`T113`), конец оператора (`T106`).
Выражения компилируются в обратной польской записи: операнды и операции
дописываются в код в порядке выполнения, а тип результата остаётся в байте
`TYPE` (`-1` целое, `0` двойная точность, `1` одинарная).

### 1.4. Разрешение ссылок вперёд

Ссылки `GOTO`/`GOSUB` на ещё не скомпилированную строку разрешаются
**цепочкой, продетой через сами незаполненные слоты операндов**:

- служебное слово записи строки в таблице = голова цепочки;
- каждый ожидающий слот операнда хранит адрес следующего ожидающего слота;
- заглушка в конце цепочки - `TOTO1` (`.WORD ENDPRG`);
- когда строка компилируется, цикл `COMPIL 1$` проходит цепочку и
  записывает во все слоты текущий адрес кода `R1`.

Направление ссылки различается в `TO 5$` сравнением `CMP 4(R4),NUMBER`:
назад (строка уже скомпилирована) - адрес известен, патчим сразу; вперёд -
включаем слот в цепочку.

дают ошибку `TRAP 12`. `MONIT` (`ADDRMN`) возвращает в монитор ПЗУ БК
(`JMP 100274`).

`SYSTEM`, `COLOR` с тремя параметрами и `SPC`; `MOTOR`, `ERASE`, `SWAP`,
`MAXFILES` в исходниках есть, но под ложными условиями или в виде
комментариев, в сборку не входят.


## Часть 2. Выполнение

### 2.1. Запуск выполнения

`R4` - указатель текущей инструкции. Чтобы начать выполнение, достаточно
выставить `R4` на первое слово кода и сделать тот же `JMP @(R4)+`, которым
заканчивается любой обработчик. Отдельной "точки входа в интерпретатор" нет.

Общий вход - `VYKDYT`/`VYK1` (`MONIT.MAC`):

```
VYKDYT::MOV	#-1,LYGIS	; программа выполняется
VYK1:	CALL	CUROFF
	CLR	INK		; сбросить код нажатой клавиши (INKEY)
	JMP	@(R4)+		; войти в шитый код с адреса R4
```

Кто и чем заряжает `R4` перед входом:

| Откуда | `R4` = | Случай |
|---|---|---|
| `ENDTXT` (`MONIT.MAC`) | `@ADRHLT` | обычный `RUN` после компиляции |
| `STATM` (`MONIT.MAC`) | `ENDCOD` | оператор прямого режима (скомпилирован в scratch-область) |
| `CONT` (`MONIT.MAC`) | `ADRHLT` | продолжение после `STOP`/точки останова |
| `BREAK`/`HALT` | `SAVJMP` | возобновление прерванной программы |

### 2.1.1. `JSR R4,STAND` - шитый код в миниатюре

Тот же механизм используется внутри подпрограмм, чтобы выполнить готовую
цепочку вызовов. `STAND` (`FLOAT.MAC`) - это ровно две инструкции:

```
STAND::	TST	(SP)+		; выбросить адрес возврата, положенный JSR
	JMP	@(R4)+		; и начать выполнять цепочку за местом вызова
```

`JSR R4,STAND` кладёт на стек старый `R4` и оставляет в `R4` адрес слова
**сразу за инструкцией вызова** - то есть начало списка адресов
подпрограмм, выписанного прямо в коде. `STAND` выбрасывает ненужный адрес
возврата и запускает этот список как обычный шитый код. Пример из `ANG`
(`GRAF.MAC`, перевод угла `CIRCLE` в координаты точки; начало):

```
	MOV	R4,SAVJMP	; свой R4 сохранить - его займёт цепочка
	JSR	R4,STAND
	.WORD	$B95		; cos(x), двойная точность
	.WORD	2$		; локальный обработчик (кусок кода в этой же подпрограмме)
	.WORD	ID		; целое -> двойная
	.WORD	$DMUL$		; умножение двойной точности
	.WORD	DI		; двойная -> целое
	.WORD	3$
	...
```

Часть слов цепочки - адреса обычных опкодов (`$B95`, `ID`, `$DMUL$`, `DI`),
часть - метки коротких кусков кода внутри самой подпрограммы (`2$`,
`3$`...), которые заканчиваются `JMP @(R4)+` и возвращают управление в
цепочку. Поскольку цепочка занимает `R4`, вызывающий обязан сохранить свой
`R4` в `SAVJMP`, а замыкающий элемент цепочки - восстановить его. Такой же
приём - в `$ARC`, `$PAINT` (вызовы `SAND`/`IDIV`), `$VALUE` (`GRAF.MAC`).

### 2.2. Диспетчер

Каждый обработчик заканчивается

```
	JMP	@(R4)+
```

- прочитать очередное слово (адрес следующего обработчика), продвинуть R4,
перейти. Централизованного цикла диспетчеризации нет: **каждый обработчик
сам является диспетчером**.

Встроенные операнды читаются тем же автоинкрементом `(R4)+` внутри
обработчика - поэтому к моменту финального `JMP @(R4)+` указатель уже
стоит на следующем опкоде.

### 2.3. Передача значений

Значения выражений передаются через **стек процессора**:

| Тип | Занимает на стеке |
|---|---|
| целое | 1 слово |
| одинарная точность | 2 слова |
| двойная точность | 4 слова |
| строка | 2 слова: длина + адрес |

Обозначения в таблицах ниже: `i` - целое (1 слово), `f` - одинарная
(2 слова), `d` - двойная (4 слова), `s` - строка (2 слова: длина, адрес).
Копирование 2 слов (`SMOV`, `SVAR`, `SFNRET`...) годится и для строки, и для
числа одинарной точности. Элемент строкового массива хранится упакованно
(3 байта: длина, адрес); `$XVAR` на чтении разворачивает его в 2 слова.

Регистры между обработчиками не сохраняются; `SAVJMP` служит ячейкой для
`R4`, когда обработчику нужен R4 под другое (`$USR`, `ANG`, `STRSQU`, `VAL`,
разбор числа в `PACK`).

### 2.4. Таблица: обработчики со встроенными операндами

Только те, кто читает операнды из потока кода; остальные - в 2.5.
Многие помимо операнда работают и со стеком - поэтому колонки
"со стека"/"на стек" здесь тоже есть.

| Обработчик | Файл | Операндов | Что читает из кода | Со стека | На стек |
|---|---|---|---|---|---|
| `JMP` | JMP | 1 | адрес перехода (`MOV @R4,R4`) | - | - |
| `JSR` | JMP | 1 | адрес перехода (после укладки кадра GOSUB; в кадре - адрес слова операнда) | - | - |
| `RTS` | JMP | 0 | (при возврате пропускает слово-операнд своего `JSR`: `NJMP`) | - | - |
| `RTSTO` | JMP | 1 | адрес перехода (`RETURN <номер>`) | - | - |
| `IFT` / `IFF` | JMP | 1 | адрес перехода (по условию - в `JMP`, иначе слово пропускается) | i | - |
| `ONJMP` / `ONJSR` | JMP | 1+N | число вариантов и слоты адресов строк | i | - |
| `DFN` | JMP | 2 | адрес продолжения (в обход тела), адрес ячейки функции | - | - |
| `FNCALL` | JMP | 2+N | адрес ячейки функции, число аргументов, затем типы аргументов | аргументы | - |
| `APAR` | JMP | 1 | смещение параметра от `PFACT` | - | адрес |
| `IPAR` / `SPAR` / `DPAR` | JMP | 1 | смещение параметра от `PFACT` | - | i / f или s / d (значение) |
| `ICONST` | JMP | 1 | целая константа | - | i |
| `SCONST` | JMP | 2 | два слова константы одинарной точности | - | f |
| `DCONST` | JMP | 4 | четыре слова константы двойной точности | - | d |
| `IVAR` | JMP | 1 | адрес ячейки переменной | - | i |
| `SVAR` | JMP | 1 | адрес ячейки (одинарная точность или строка) | - | f / s |
| `DVAR` | JMP | 1 | адрес ячейки переменной | - | d |
| `IMOV` | JMP | 1 | адрес ячейки-приёмника | i | - |
| `SMOV` | JMP | 1 | адрес ячейки-приёмника (2 слова) | f / s | - |
| `DMOV` | JMP | 1 | адрес ячейки-приёмника | d | - |
| `INDEX` | JMP | 2 | адрес записи массива, число индексов | индексы | адрес элемента |
| `ARRAY` / `ARR10` | JMP | 2 | адрес записи массива, число измерений | границы | - |
| `FORINT` / `FORDBL` | JMP | 2 | слот продолжения цикла (адрес тела), адрес счётчика | предел, шаг | - (в кадр `CIKL`) |
| `NXSKIP` | JMP | 1 | адрес переменной из `NEXT` (0 - без переменной) | - | - |
| `NEXSNG` | JMP | 0 | (пропускает следующие два слова-опкода `NEXCMP`/`NEXJMP`) | - | - |
| `RESTV` | JMP | 1 | адрес `DATA` (или 0 - не найден) | - | - |
| `READV` | JMP | 1+N | конец списка переменных, затем адреса переменных-приёмников | - | - |
| `GET` / `GETLIT` | JMP | 1+N | конец списка переменных, затем адреса переменных (для элементов массива - `GETARR`) | - | - |
| `$DEFUS` | JMP | 1 | адрес ячейки `USRTAB`, куда записать адрес подпрограммы | i | - |
| `$USR` | JMP | 2 | номер USR-функции, доп. слово (в `R3`, не выяснено) | аргументы | результат |
| `USEROM` | BK | 1 | адрес текста оператора `CALL` | - | - |

Примечания к отдельным строкам:

- Константы кладут на стек **столько слов, сколько у типа**: `ICONST` - 1,
  `SCONST` - 2, `DCONST` - 4 (код общий, падает вниз от `DCONST` к
  `ICONST`).
- `APAR` кладёт на стек **адрес** параметра (для передачи по ссылке),
  тогда как `IPAR`/`SPAR`/`DPAR` - его **значение**.
- `FORINT`/`FORDBL` не оставляют значений на стеке: предел, шаг и два
  операнда из кода укладываются в кадр цикла (область `CIKL`).
- `INDEX` заменяет лежащие на стеке индексы вычисленным адресом элемента;
  дальше значение читает/пишет соответствующий `*XVAR`/`*XMOV`.
- `DFN` вообще не трогает стек: он лишь регистрирует адрес тела функции в
  ячейке переменной и перепрыгивает через тело по первому операнду.
- Список переменных `READV`/`GET` имеет вид: слово "конец списка", затем
  адреса целей; для элемента массива в поток вставлен опкод `GETARR`, и
  адрес элемента приходит со стека. Структура проверена в общих чертах.

### 2.5. Таблица: обработчики, работающие только через стек

Большинство опкодов операндов из потока не читают - берут аргументы со
стека и кладут туда же результат.

**Арифметика и логика целых** (`JMP.MAC`)

| Опкод | Со стека | На стек | Примечание |

| `INEG` / `IABS` / `ISGN` | i | i | смена знака / модуль / знак числа: -1/0/1 |
| `NOT` | i | i | побитовое НЕ |
| `OR`, `AND`, `XOR`, `EQV`, `IMP` | i, i | i | побитовые операции (`AND` - через инверсию и `BIC`) |

| Опкод | Со стека | На стек | Примечание |
|---|---|---|---|

| `ID` / `IS` | i | d / f | преобразование целого |
| `SD` | f | d | одинарная в двойную |

`+ - *`, когда оба операнда целые; `/` и `^` - всегда двойной точности

### 2.6. Совмещённые механизмы

**Стек кадров.** `FOR` и `GOSUB` укладывают кадры в одну область, растущую
вниз к `ENDCOD` (`CIKL` - вершина, `LIMIT` - текущий кадр `GOSUB`).
Кадр `GOSUB` - 2 слова (адрес возврата, прежний `LIMIT`). Кадр `FOR` -
4 слова для целого счётчика и 10 слов для нецелого (`FORINT`/`FORDBL`).
Различаются только тем, какой опкод их потом снимет, поэтому `NXSKIP`
проходит мимо чужих кадров, отыскивая нужный цикл (размер кадра он
определяет по биту типа в слове имени переменной).

**Самомодификация кода.** Компилятор разрешает ссылки вперёд, дописывая
адреса прямо в незаполненные слоты операндов (см. 1.4); `FOR` записывает
в слот продолжения адрес тела цикла. `HCOR` (`BK.MAC`) подменяет слово
кода переходом на `STPEND` - так реализованы точки останова `STEP`/`TRON`;
`SEPAP` возвращает слова на место и сбрасывает стек интерпретатора при
любом выходе из выполнения.

**Вызов цепочки подпрограмм.** `JSR R4,STAND` - см. 2.1.1.

**Обработка ошибок и повторы.** `TRAP N` с `N < 100` - код ошибки (`ERROR`
в `TRAP.MAC`). Ошибка во время выполнения определяет строку по адресу
в `R4` (или в `SAVJMP` у операторов ввода) и возвращает управление в
монитор. Ошибка 13 при вводе с клавиатуры (`INPUT`) не заканчивает
оператор: `GETERR` возвращается в программу, а `G4` (`JMP.MAC`) повторяет
оператор по `SAVJMP`. В ПЗУ 1986.07.24 повтор начинается на слово раньше -
с `$SQUEE`, то есть со сборки мусора строк (`JMP @-4(R4)` вместо
`JMP @-2(R4)`); см. `../BASIC-BK-0010-19860724/README.md`.


## Что остаётся невыясненным

- Точная разрядность/формат отдельных операндов у `READV`/`GET`,
  `ONJMP`/`ONJSR`, `FNCALL` - структура понятна, побайтная раскладка
  проверена не полностью.
- Второе слово-операнд `$USR` (`R3`).
- Смысл спецобработки `REM`/`'`/`DATA` в `SET1` (`MONIT.MAC`).
- Сквозное описание `PFACT`/`TYPE` в компиляции выражений.
- Слот продолжения (`ASTAR+2`) в `FOR`: роль подтверждена по использованию в
  `NEXJMP`/`NEXINT`, но не по самому коду `FOR`.
