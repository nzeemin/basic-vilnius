# BASIC-BK-ROM-UNKNOWN: неизвестная версия Бейсика БК-0010

Три образа ПЗУ для БК-0010 (К573РФ3, по 8 КБ, `120000`–`177777`). Происхождение и версия неизвестны; предположение владельца: предварительная версия обычного Бейсика Вильнюс.

## Файлы

| Файл | Что |
| --- | --- |
| `DS18.bin`, `DS19.bin`, `XT18.bin` | исходные дампы прошивальщика, 8194 байта (последние 2 байта: `00dd`, `01dd`, `02dd`; смысл не выяснен, декодер их не использует) |
| `basic10_1.rom` = `XT18`, `basic10_2.rom` = `DS18`, `basic10_3.rom` = `DS19` | декодированные образы, 8192 байта. Декодер: `D:\Work\Debug\DumpBasicBk\Program.cs` (инверсия байтов, слова в обратном порядке: `res[a]=~ds[~a&1ffe]`, `res[a+1]=~ds[~a&1fff]`); пересчёт проверен, совпадает побайтно |
| `basic-rom.bin` | три ПЗУ подряд в формате BK `.bin`: адрес `120000`, длина `24448` (до `177577`, остальные 128 байт третьего ПЗУ нулевые) |
| `names.txt` | ручные имена и комментарии (вход генератора) |
| `basic-rom.dis.lst` | листинг (генерируется, руками не править) |

Пересборка листинга (из корня репозитория; база `BASIC-BK-0010-19860724/build/BASIC.MAP` должна быть собрана):

```bash
python x-bkrom-build.py BASIC-BK-ROM-UNKNOWN
```
Скрипт делает `basic-rom.bin`, сопоставление с базовым ПЗУ (`x-matchbase.py`), `x-dis2.py` с `TRAPSTYLE=base` и проверку обратной сборкой (`x-dis2-verify.py`): должно быть `differing 0`. Сейчас: 24448 байт, код 86% (7808 инструкций), расхождений 0.

В отличие от БЕЙСИК 85/87, здесь `TRAP` устроен как в базовом ПЗУ: `TRAP 101` — одно слово-операнд, `TRAP 103` — без операнда, `TRAP 113` — два слова (таблица слов, режим/последнее слово). Это включает `TRAPSTYLE=base` в `x-dis2.py`.

## Что установлено

- ПЗУ запускается в эмуляторе (`conf:BK-0010-BASIC`, подменённые `basic10_1..3.rom`): заголовок `BASIC-BK`, затем `Ok`. Строка статуса `CAGLRCCC.R` выводится самой прошивкой.
- Вход `120000`: `JMP` на `122716`; там блок `START` из базового ПЗУ (в базовом ПЗУ `START` стоит прямо в `120000`).
- Близкий родственник базового ПЗУ BASIC-BK-0010-19860724: около 83% инструкций (6264 из 7593 до уточнения `TRAP`) входят в общие цепочки с базовым ПЗУ (`x-matchbase.py`), но порядок блоков **другой** (совпадают единицы байт по тем же адресам).
- Заголовок: `BASIC-BK` (в базовом `БЕЙСИК (Вильнюс,1986.07.24)`); даты нет.
- Таблица имён операторов `OPRNAM` стоит в самом начале ПЗУ (`120134`), в базовом `132733`. 58 слов, порядок свой. Есть слова, которых нет в таблице базового ПЗУ: `SOUND MOTOR MERGE ERASE SWAP`; нет слов `TRON TROFF CALL _`. В исходниках базового Бейсика `MOTOR MERGE ERASE SWAP MAXFILES` закомментированы (условно не входят в сборку).
- Таблица функций: `PI POINT INP PEEK BASE RND ... INSTR VARPTR USR FN INKEY MID STRING STR CHR BIN OCT HEX` (в базовом ПЗУ `PI POINT INP PEEK RND ...`; добавлены `BASE`, `INSTR`, `VARPTR`).
- Таблицы операторов разобраны, см. `comparison.md`: `AOPNAM` `121442`, `ATRAP` `121630` (таблица `TRAP`, а не операторов), `AOPSUB` `122270` (единая, 59 слов), `AOPMON` `122526`. Метки `C.слово`/`M.слово` в листинге ставит `x-bkrom-names.py`.

## Не сделано

- Построчное сравнение с базовым ПЗУ (какие блоки отличаются, что изменено внутри совпавших цепочек).
- Содержимое обработчиков (в том числе новых `SOUND`, `MOTOR`, `ERASE`, `SWAP`, `MERGE`) не читалось.
- Сравнение с БК-0011М (`BK/basic11m_*.rom`): там тоже есть `MERGE`.
