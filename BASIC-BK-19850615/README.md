# БЕЙСИК 85

Образ `basic01bk.bin`: Бейсик Вильнюс для БК-0010, баннер «ВИЛЬНЮС,1985.06.15». BIN-файл БК-0010: первые два слова — адрес загрузки (`015174`) и длина (`022520`, 9552 байта); после данных лежит слово контрольной суммы ленты (`0x719e`). Образ грузится в ОЗУ и запускается с `015174` на машине с ПЗУ Фокала. Исходников и описания нет. Основное описание устройства (таблицы операторов, обработчики, `TRAP`-библиотека, выражения, монитор, вывод чисел) — в `../BASIC-BK-19870225/README.md`: у 85 то же самое, кроме перечисленного ниже.

## Файлы и инструменты

| Файл | Что это |
| --- | --- |
| `basic01bk.bin` | образ (только для чтения) |
| `basic01bk.dis.lst` | аннотированный листинг, генерируется (адрес, до трёх слов, инструкция, через табуляцию) |
| `names.txt` | имена и комментарии, **получены** из `../BASIC-BK-19870225/names.txt` скриптом `x-focal-xlate.py` по совпадению байт кода; не править вручную |

```bash
PYTHONIOENCODING=utf-8 python x-focal-xlate.py BASIC-BK-19870225/basic02bk.bin BASIC-BK-19870225/names.txt BASIC-BK-19850615/basic01bk.bin > BASIC-BK-19850615/names.txt
python x-focal-build.py BASIC-BK-19850615/basic01bk.bin
```

Первая команда пишет `names.txt`, вторая собирает листинг и проверяет его обратной сборкой `macro11`. Строки, для которых в 85 нет соответствия, при переносе пропускаются (сообщения идут в stderr).

## Отличия от БЕЙСИК 87

- Баннер `ВИЛЬНЮС,1985.06.15`, приглашение `:` (в 87 `Версия от 25.02.87` и `#`).
- Образ длиннее на 16 байт (9552 против 9536).
- Несколько операторов в строке не поддерживаются (`A=5:PR A` даёт ошибку `03`); в 87 вызов оператора обёрнут проверкой разделителя (`COMPST`, `KODTST`).
- `ATA(1)` = `0.7853981`, верно; в 87 в `R.ATA` смещение `10006(SP)` вместо `6(SP)` (слово `036362`), и `ATA(1)` = `1.000484`.
- Остановка по КТ (`KBDHK`, `BRKHND`, `TRCTRP`, `RUNGO`) та же по смыслу; в 87 части лежат в хвосте образа (`037404` и далее), у 85 по этим адресам других подпрограмм нет.
- Остальное (таблицы слов и операторов, `TRAP`-библиотека, обработчики, вычисления) совпадает с 87 по тем же адресам.

Различаются 214 байт образов: начальный код, перенос части подпрограмм в хвост 87, смещение в `R.ATA` и добавленный в 87 разбор разделителя оператора.

## Прогон в эмуляторе

Через `x-bkbtl-debugger/x-focal-run.py` (`conf:BK-0010-FOCAL`, образ без слова контрольной суммы, `PC = 015174`). Приглашение `:`.

| Проверка | Результат |
| --- | --- |
| Число цифр | 7: `1/3` = `0.3333333`, `123456789` = `0.1234568E 09` |
| `SQR(2)`, `SIN(1)`, `TAN(1)`, `ATA(1)`, `EXP(1)`, `LOG(10)` | `1.414214`, `0.841471`, `1.557408`, `0.7853981`, `2.718282`, `2.302585` |
| `1/0`, `SQR(-1)` | ошибки `14`, `15` |
| Вывод мантиссы `0.1` | теряется `.1`: `1E10` = `0E 11`, `1E15` = `0E 16`, `0.00001` = `0E-04` (как у 87; причина не найдена) |
| `PEEK`, `LEN`, `ATN`, `MOD`, `AND` | ошибки `46`/`45` |
| `A=5:PR A\PR A*2` | ошибка `03` |
| `PR` вместо `PRINT` | работает |

`LIST`, `RUN`, `SAVE`/`LOAD`, `KEY` в эмуляторе не запускались.
