# БЕЙСИК 87

Образ `basic02bk.bin`: Бейсик Вильнюс для БК-0010, баннер «Версия от 25.02.87». BIN-файл БК-0010: первые два слова — адрес загрузки (`015174`) и длина (`022500`, 9536 байт); после данных лежит ещё слово контрольной суммы ленты (`0x7a4a`). Образ грузится в ОЗУ и запускается с `015174` на машине с ПЗУ Фокала. Исходников и описания нет, всё ниже выведено из кода образа и из прогона в эмуляторе. Параллельная версия 1985 года — `../BASIC-BK-19850615/` (отличия в её `README.md`). Таблицы сравнения с базовым Бейсиком и другими версиями вынесены в `../BK/versions-comparison.md`.

## Файлы и инструменты

| Файл | Что это |
| --- | --- |
| `basic02bk.bin` | образ (только для чтения) |
| `basic02bk.dis.lst` | аннотированный листинг, генерируется; строки: адрес, до трёх слов, инструкция, через табуляцию |
| `names.txt` | ручные имена и комментарии, вход генератора (править его, а не листинг) |

Листинг собирается скриптами из корня репозитория:

```bash
python x-focal-build.py BASIC-BK-19870225/basic02bk.bin
```

Цепочка: `x-matchbase.py` (общие подпрограммы с базовым ПЗУ), `x-focal-names.py` (таблицы операторов), `names.txt`, `x-dis2.py` (рекурсивный дизассемблер), `x-dis2-verify.py` (обратная сборка `tools/macro11.exe -ysl 16`, сравнение слов с образом). Листинг годен, только если проверка печатает `differing 0`. В `names.txt`: `N` имя, `K` комментарий над меткой, `C` комментарий в строке `.WORD`, `X` принудительная точка входа, `W`/`D`/`B` таблицы слов, чисел и байтов; `?` в комментариях означает «выведено из кода, не проверено запуском». Для 85 файл `names.txt` создаётся из этого переносом (`x-focal-xlate.py`).

Запуск образа в эмуляторе (`x-bkbtl-debugger`):

```bash
python x-bkbtl-debugger/x-focal-run.py BASIC-BK-19870225/basic02bk.bin out.png "PRINT 2+2"
```

Образ загружается без слова контрольной суммы (`loadbin` его не принимает), `PC = 015174`, строки вводятся с клавиатуры, снимается экран.

## Прогон БЕЙСИК 85 и 87 в эмуляторе

Образы загружались в `x-bkbtl-debugger/bkbtldebug.exe` (`conf:BK-0010-FOCAL`) скриптом `x-bkbtl-debugger/x-focal-run.py`: `loadbin` (без хвостового слова контрольной суммы ленты, которое есть в обоих файлах: `0x719e` в 85, `0x7a4a` в 87), затем `PC=015174`. Приглашение: `:` в 85, `#` в 87. Строки вводились с клавиатуры, результат смотрелся по скриншоту.

| Проверка | БЕЙСИК 85 | БЕЙСИК 87 |
| --- | --- | --- |
| Число цифр | 7 (`1/3` = `0.3333333`, `123456789` = `0.1234568E 09`) | то же |
| `1/0`, `SQR(-1)` | ошибки `14`, `15` | то же |
| Вывод мантиссы `0.1` | цифра `1` теряется: `1E10` = `0E 11`, `1E9` = `0E 10`, `0.00001` = `0E-04` | то же |
| `ATA(1)` | `0.7853981` (верно) | `1.000484` (неверно) |
| `SQR(2)`, `SIN(1)`, `TAN(1)`, `EXP(1)`, `LOG(10)` | `1.414214`, `0.841471`, `1.557408`, `2.718282`, `2.302585` | то же |
| `ABS SGN INT RND PEK STR HEX CHR AT` | работают | работают |
| `PEEK`, `LEN`, `ATN`, `MOD`, `AND` | ошибки `46`/`45` | то же |
| Несколько операторов в строке (`A=5:PR A\PR A*2`) | ошибка `03` | работает |
| `LET` можно опустить | не проверялось | работает (`A=5`) |
| `PR` вместо `PRINT` | работает | работает |

Проверены только прямые команды. `LIST`, `RUN`, `SAVE`/`LOAD`, `KEY` в эмуляторе не запускались; `DIM`, `DOT`, `LINE`, `FOR`/`NEXT`, `LET`, `PRINT`, `INPUT`, `RANDOMIZE` и выражения разобраны по коду.

| Таблица | Адрес | Содержимое |
| --- | --- | --- |
| `OPRNAM` | `016352` | имена: `CLEAR CONTINUE DIMENSION LINE EDIT END FIND FOR GOSUB GOTO IF INPUT LET LIST LOAD MONITOR NEXT DOT PRINT RANDOMIZE REMARK RETURN RUN SAVE POKE OUT STOP` |

Подпрограммы компиляции (`C.xxx`) записывают адрес исполняющего обработчика через `MOV #addr,(R1)+`, как `COMP.MAC` базы: `C.GOSUB` кладёт `026506`, `C.GOTO` `026510`, `C.RETURN` `026514`, `C.STOP` `026204`, `C.END` `026176`, `C.POKE` и `C.OUT` соответственно `POKJMP` и `OUTJMP` (имена из базы, совпали).

Особые значения в таблицах:

| Адрес | Имя в листинге | Где встречается |
| --- | --- | --- |
| `017576` | `ERR04` (`TRAP 4`) | `AOPSUB`: `CLEAR CONTINUE EDIT FIND LIST LOAD MONITOR RUN SAVE` (команды монитора, в программе недопустимы). `AOPMON`: `END FOR NEXT RETURN STOP` (прямо не выполняются) |
| `020050` | `M.EXEC` | `AOPMON`: `DIM LINE INPUT LET DOT PRINT RANDOMIZE POKE OUT` — общий вход «скомпилировать и выполнить» |

Для разбора этих таблиц потребовалось исправить обход в `x-dis2.py`: после `TRAP n` и `JSR Rn,...` могут идти 1–3 команды `BR` — слоты пропуска возврата, код продолжается после каждой из них (идиома базы). Покрытие кода листингом выросло с 74% до 84%.


## Рантайм-обработчики БЕЙСИК 87 и 85 (нитевой код)

Область `026176`–`027520` (образ 87; в образе 85 адреса те же). Обработчик оканчивается `JMP @(R4)+`, операнды читаются из потока кода через `(R4)+`, значения идут через стек. Имена `R.xxx` и комментарии — в `BASIC-BK-19870225/names.txt` (для 85 файл получен `x-focal-xlate.py`). Строки с `?` в комментариях выведены только из кода.

| Адрес | Имя | Что делает |
| --- | --- | --- |
| `026176` / `026204` | `R.END` / `R.STOP` | `END` сбрасывает адрес продолжения; `STOP` запоминает `R4` (для `CONTINUE`), печатает «стоп в строке N» (подпрограмма `PRTLIN`, `026242`) и возвращает в монитор |
| `026440` | `CMPTAB` | таблица переходов по результату сравнения: `=` `>` `<` `>=` `<=` `<>` (`B.EQ`, `B.GT`, `B.LT`, `B.GE`, `B.LE`, `B.NE`); те же символы лежат в строке `=><` на `022474` |
| `026506` / `026510` / `026514` / `026516` | `R.GOSUB` / `R.GOTO` / `R.RETURN` / `R.SKIP` | вызов подпрограммы кладёт `R4` в стек; переход берёт адрес из потока; возврат снимает `R4`; `R.SKIP` пропускает операнд перехода при ложном условии |
| `026544`, `026724`, `026752` | `R.PUSHI`, `R.PUSHS`, `R.STORS` | значение целой переменной в стек, значение Single (2 слова) в стек, запись Single в переменную (используется в `LET` и `FOR`) |
| `026710` / `026712` | `R.CNST2` / `R.CNST1` | константа Single (2 слова) или целая (1 слово) из потока кода в стек |
| `026774`, `027006`, `027504` | `R.PRTNL`, `R.PRTNUM`, `R.PRTSTR` | `PRINT`: перевод строки, число, строка |
| `027046`, `027452` | `R.INPUT`, `R.INPITM` | `INPUT`: вывод `?`, ввод строки, разбор элементов через запятую (ошибка 11 при недопустимых знаках) |
| `027472` | `R.RANDOM` | `RANDOMIZE`: сбросить затравку генератора |

Инструменты: `x-focal-build.py` собирает листинг (совпадения с базой, таблицы операторов, `names.txt`) и проверяет его обратной сборкой `macro11`; `x-focal-xlate.py` переносит `names.txt` между 85 и 87.


Добавлено (FOR/NEXT, DIM, LET, DOT, LINE; `names.txt`):

- **`FOR`/`NEXT`** не имеют собственных исполняющих обработчиков. `C.FOR` разбирает `имя = выражение TO предел [STEP шаг]` и собирает цикл из общих операций (`R.STORS` и др.); открытые циклы лежат в цепочке с головой в слове `015152`. `C.NEXT` находит нужный `FOR` по имени и выдаёт код: значение плюс шаг (`R.ADDS`), `R.STORS`, сравнение с пределом (`SCMP`, сравнение Single), `R.FORTST` и переход к началу цикла.
- **`DIM`** (`C.DIM`) только разбирает список размеров (до `100` восьмеричное, по умолчанию 16) и кладёт размеры в поток кода; исполняемого кода нет.
- **`DOT`** и **`LINE`** (`C.DOT`, `C.LINE`): два выражения через `SI` (Single в целое), необязательный третий параметр `A` (по умолчанию 1), затем `R.PMODE` (режим из `A`: символ `0220+A`) и обработчик `R.DOT` (`016240`, `EMT 30`) либо `R.LINE` (`016252`, `EMT 32`). Номера `EMT` взяты из кода; назначение функций монитора БК не проверялось.
- `TRAP 113` сопровождается встроенной строкой (`THEN`, `TO`, `STEP`), заканчивающейся нулём и дополненной до чётного. Дизассемблер теперь учитывает это, покрытие кода в листингах стало 86% (87) и 85% (85).
- В базе `SCMP` — сравнение Single (`S` — Single), не строк; комментарий в `names.txt` исправлен.

Неразобранными остаются обработчики внутри `PRINT` (область `021720`–`022040`: `AT`, `TAB`, `CHR`, разделители) и большая часть библиотеки `TRAP`.


## Библиотека TRAP и PRINT в БЕЙСИК 85/87

Вход `TRAP` (`023474`) совпадает с базовым (`TRAP::` в `TRAP.MAC`): код возврата R0 подменяет адрес возврата, поэтому после `TRAP n` идут слоты пропуска, а коды меньше `100` — номера ошибок (печатаются как `ОШИБКА nn`). Таблица `ATRAP` (`023776`) в БЕЙСИК 85/87 содержит всего 14 обработчиков, `TRAP 100`–`115`, и **номера не совпадают с базовыми** (в базе `TRAP 103` — ссылка на переменную, в БЕЙСИК 85/87 это поиск слова в таблице; ссылка на переменную в БЕЙСИК 85/87 — `TRAP 107`):

| TRAP | Адрес | Что делает в БЕЙСИК 85/87 |
| --- | --- | --- |
| `100` | `024122` | разбор выражения (унарный минус даёт `R.NEGS`) |
| `101` | `024072` | текущий символ из байтовой таблицы (операнд после `TRAP` — адрес таблицы) |
| `102` | `024032` | классификация символа: цифра — пропуск двух слов, буква — одного |
| `103` | `024546` | слово `R5` из таблицы слов (операнд — адрес таблицы, конец — нулевое слово) |
| `104` | `024574` | найти или завести переменную |
| `105` | `024740` | разбор имени (до двух знаков) в `R5` |
| `106` | `025066` | конец оператора |
| `107` | `025102` | ссылка на переменную: простая, строковая, элемент массива |
| `110` | `025260` | разбор десятичного числа (номера строки) |
| `111` | `025342` | поиск номера строки в таблице |
| `112` | `025374` | пропуск пробелов |
| `113` | `025406` | сравнение с встроенным словом (после `TRAP` идёт слово до нуля, выровненное на слово; допускается сокращение). В базе тут операнд-адрес таблицы |
| `114` | `025466` | вывод числа `R5` в десятичном виде |
| `115` | `025576` | строковый литерал в кавычках |

Для дизассемблера это значит, что операнд после `TRAP 101` и `TRAP 103` — слово данных, после `TRAP 113` — строка, а слоты пропуска могут содержать не только `BR`, но и `RETURN` (после `TRAP 102`).

`PRINT` (`C.PRINT`, `021554`): элемент — строка (`TRAP 115`, затем `R.PRTSTR`), функция `AT`/`TAB`/`CHR` (по таблице слов `022026`, обработчики из таблицы `022042`: `R.TAB` `016172`, `R.AT` `016176`, `R.CHR` `030276`) или выражение (`R.PRTNUM`); в конце `R.PRTNL`, если нет `;` или `,`. `AT` и `TAB` в монитор БК обращаются через `EMT 24` (установка курсора) и `EMT 26` (чтение позиции), по коду.


## Выражения и функции БЕЙСИК 87 и 85

Разбор выражения: рекурсивный спуск по четырём уровням (адреса образа 87):

| Уровень | Адрес | Операции |
| --- | --- | --- |
| сложение | `T100` (`024122`) | `+` `-`, унарный минус даёт `R.NEGS`; знаки в байтовой таблице `OPADD` (`024540`) |
| умножение | `E.TERM` (`024176`) | `*` `/`, знаки в `OPMUL` (`024543`) |
| степень | `E.POWER` (`024226`) | `^`, обработчик `R.POW` (`037000`) |
| первичное | `E.PRIM` (`024260`) | число (`E.NUM`, `030454`), переменная, функция, `(` выражение `)` |

Обработчики уровней — в таблицах `ADDTAB` (`032322`: `R.ADDS`, `R.SUBS`) и `MULTAB` (`032326`: `R.MULS`, `R.DIVS`), функции — в `FUNTAB` (`032332`). Имена функций лежат в `FUNNAM` (`024502`) по три знака в упакованном виде: знак `A`..`Z` = 1..26, слово = (c1·40 + c2)·40 + c3, а индекс слова — индекс обработчика. Набор: `RND SQR SIN COS TAN ATA EXP LOG ABS SGN INT PEK IN KEY` (14 функций, `IN` из двух знаков).

| Функция | Обработчик |
| --- | --- |
| `RND` | `R.RND` `036656` |
| `SQR` `SIN` `COS` `TAN` `ATA` | `R.SQR` `035262`, `R.SIN` `035456`, `R.COS` `035422`, `R.TAN` `036600`, `R.ATA` `036010` |
| `EXP` `LOG` | `R.EXP` `034126`, `R.LOG` `034506` |
| `ABS` `SGN` `INT` | `R.ABS` `034076`, `R.SGN` `034104`, `R.INT` `036510` |
| `PEK` `IN` `KEY` | `R.PEK` `030346`, `R.IN` `030356`, `R.KEY` `030314` |

**Причина ошибки `ATA` в 87.** Вещественная арифметика 85 и 87 совпадает, кроме одного слова по адресу `036362`. В `R.ATA` у 85 стоит `MOV (SP)+,6(SP)`, у 87 `MOV (SP)+,10006(SP)`: в слове смещения установлен лишний бит (`010006` вместо `000006`), значение пишется далеко от стека, поэтому `ATA(1)` даёт `1.000484` вместо `0.785398`. Версия 85 считает арктангенс правильно.

## Монитор, ввод-вывод и прерывание по КТ (БЕЙСИК 87)

Адреса образа 87; имена в `BASIC-BK-19870225/names.txt`. Все обращения к экрану, клавиатуре и ленте идут через вызовы монитора БК (`EMT`): `EMT 6` — ждать клавишу, `EMT 16` — вывести символ, `EMT 20` — вывести строку, `EMT 36` — магнитофон по блоку параметров `0320`.

| Адрес | Имя | Что делает |
| --- | --- | --- |
| `015270` | `IVEIL` | ввод строки в буфер `001000` (до 81 знака) с редактированием |
| `015702` / `015706` | `ISV` / `ISVEIL` | вывод символа `R0` / строки (`R1` адрес, `R2` длина) |
| `017044` | `MONIT` | баннер и вход в основной цикл `M.REM` (`017064`; в базе `STAR`): приглашение (`#` в 87, `:` в 85), `IVEIL`, `ANALIZ` |
| `017110` | `ANALIZ` | есть ли номер строки: нет — команда (`KEYFND`, переход по `AOPMON`), есть — вставить, заменить или удалить строку в таблице строк (с `015140` вниз, 3 слова на строку; `LINDEL` удаляет запись) |
| `017424` | `KEYFND` | поиск слова-команды в `OPRNAM` по введённому тексту (допустимы сокращения) |
| `017612` | `CLRTXT` | сброс текста программы и указателей (`015140`, `015142`, `015144`, `015156`, `015160`) |
| `017652` | `M.LIST` | печать по 16 строк, затем приглашение; Enter — ещё 16 |
| `020140` | `M.RUN` | компиляция всех строк по таблице строк (оператор вызывается через `AOPSUB`, у `REMARK` вход — в середину цикла), потом запуск (`RUNGO`, `037622`: `MTPS #0` и `JMP @(R4)+`) |
| `020556`, `020762`, `020774` | `M.LOAD`, `M.FIND`, `M.SAVE` | лента через блок `0320`; `GRBCOL` (`021032`) перед записью переписывает строки подряд, убирая «мусор» после правок |
| `021346` | `M.EDIT` | вывод строки в буфер ввода для правки |

**Остановка по КТ.** Слово `0260` указывает на `KBDHK` (`015712`): код клавиши `3` (КТ) запускает `BRKHND` (`037512`), другие коды запоминаются в `015170` (из него читает функция `KEY`). `BRKHND` переводит процессор в пошаговый режим (вектор `14` = `TRCTRP`, `037550`; T-бит в сохранённом PSW) и доходит до ближайшей команды `JMP @(R4)+` внутри кода программы, где подставляет `R.STOP`: печатается «стоп в строке N». Так остановка всегда приходится на границу команды нитевого кода.

**В 87 добавлено:** `COMPST` (`037444`) вместо прямого `CALL @AOPSUB(R2)` — вызов с проверкой разделителя оператора (`KODTST`, `022454`, таблица `037507`): это и даёт несколько операторов в строке. Участки `KBDHK`/`BRKHND`/`TRCTRP`, `COMPST` и `KODTST` отсутствуют по этим адресам в 85, поэтому в `names.txt` для 85 их нет.

## Вывод чисел и математика (БЕЙСИК 87 и 85)

**Вывод Single.** `R.PRTNUM` (`027006`) вызывает `NUMFMT` (`031342`, аналог `UNPCK` базы): 7 значащих цифр, формат без порядка или `0.ddddddd E nn`. Помощники: `MUL5`/`MUL10E` (`031232`, `031204`), `DIV10` (`031256`), сдвиги `SHR1`/`SHR2` (`031332`, `031326`), цифра очередного разряда — пара `MANX5` (`032012`, x + x/4) и `MANX8` (`032042`, сдвиг на 3) в сумме умножают мантиссу на 10, цифра попадает в `R4`; `ROUND7` (`032064`) округляет, `DIGOUT` (`032216`) пишет цифры, ставит точку и обрезает хвостовые нули, `SIGNST` (`032172`) — знак. Буфер текста — слова `001120`…, адрес и длина поля передаются через стек.

**Потеря «.1» в E-формате** (`PRINT 1E15` даёт `0E 16`, а `2E15` даёт `0.2E 16`; то же для `1E10`, `1E9`, `0.00001`). Проверено в эмуляторе с точкой останова на `DIGOUT`: на выходе цикла цифр буфер содержит правильную строку `-0.1000000`, значит цифры формируются верно. Различие между случаями видно в конце `DIGOUT` (`032320`): для `1E15` указатель конца `R3 = 001124` (обрезка по последней ненулевой цифре), для `2E15` `R3 = 001126` (ещё два нуля). Дефект лежит после цикла цифр, в обрезке нулей или в сборке `E nn`; точное место не найдено. Одинаково в 85 и 87.

**Математика.** Функции построены на нитевом мини-коде: `JSR R4,STAND` (`STAND`, `036504`, как в базе) и следом слова-обработчики (`R.MULS`, `R.SUBS`, `R.DIVS`, константы Single и адреса ветвлений), поток оканчивается адресом команды сразу за ним. Дизассемблер теперь распознаёт такие потоки (`JSR R4` на процедуру из `TST (SP)+` и `JMP @(R4)+`): покрытие кода в 87 выросло до 90%. Коэффициенты многочленов лежат в таблицах констант рядом (например `036460`–`036502`).
