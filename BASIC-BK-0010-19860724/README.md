# Воссоздание исходников Бейсик Вильнюс для БК-0010 (ПЗУ 1986.07.24)

Цель: из исходников собрать ПЗУ, **побайтно** совпадающее с `../BK/basic10_1.rom`, `basic10_2.rom`, `basic10_3.rom` (24448 байт, адреса `120000`–`177577`).
Статус: **достигнуто**, `!verify.cmd` показывает 0 расхождений.

Основа — копия `../BASIC-BK-1985/` (исходники 1985 года). Оригинал не тронут; все правки только здесь.

## Сборка

```
!build.cmd     ассемблирует модули в build\*.OBJ (BOM снимается во временные копии build\src)
!link.cmd      линкует в build\BASIC.SAV (плоский образ памяти 64 КБ), карта build\BASIC.MAP
!verify.cmd    сравнивает диапазон 120000..177577 образа с ../BK/basic10_*.rom (x-romcmp.py)
```

Инструменты: `../tools/macro11.exe`, `../tools/pclink11.exe`. Python только для вспомогательных скриптов
(`x-romcmp.py` — сравнение, `x-order.py` — подбор порядка линковки перебором).

Особенности инструментов:
- `macro11` не принимает UTF-8 BOM, поэтому `!build.cmd` ассемблирует копии без BOM.
- `pclink11` ломается на путях с `D:`, поэтому `!link.cmd` работает из `build\` с относительными путями.
- Образ `.SAV` у `pclink11` — плоская память 64 КБ, ПЗУ лежит по своим адресам.

## Структура модулей

- **`BK.MAC` + `GRAF.MAC` — один модуль.** `BK.MAC` кончается внутри открытого `.IF EQ,MASINA-BK0010` и
  комментарием «продолжение в другом файле»; `GRAF.MAC` лишним `.ENDC` закрывает его и содержит `.END START`.
  Оригинал собирался как `MACRO BK+GRAF`.
- Остальные модули (`COMP`, `FLOAT`, `JMP`, `MONIT`, `TRAP`) собираются отдельно: в них совпадают
  локальные метки (`GO`, `OUT`, `FIND`…), в одном модуле это дало бы ошибки.
- **Порядок линковки:** `BK MONIT COMP TRAP JMP FLOAT TAIL` (найден перебором всех перестановок: этот порядок
  даёт минимум расхождений; положение `BK` не важно, он целиком в ABS-секции).
- `BK` — абсолютная секция (`START=120000`), остальное — релоцируемые секции, идущие за ней по порядку линковки.

## Отличия исходников 1985 от ROM 1986.07.24

Каждое место помечено комментарием в коде.

| Файл | Место | Исходник 1985 | ROM 1986 | Тип |
| --- | --- | --- | --- | --- |
| `COMP.MAC` | `TRON::` | `НOV` (кириллическая Н) | `MOV` | порча кодировки при конвертации |
| `BK.MAC` | проверка суммы у `START` | `BEQ 2$` | `BR 2$` | проверка отключена |
| `BK.MAC` | `SUM1` | `0` | `102657` | контрольное слово (из дампа) |
| `COMP.MAC` | `SUM2` | `0` | `37716` | контрольное слово (из дампа) |
| `JMP.MAC` | после `G4:` | `JMP @-2(R4)` | `JMP @-4(R4)` | отличие версий |
| `FLOAT.MAC` | `$APPRX`, `.WORD 0,0,0,0` | последнее слово `0` | `360` | мёртвое слово: пропускается `BR 1$`, никем не читается; в ROM БК-0011М там `0` |
| `TAIL.MAC` | после кода `FLOAT` | нет | слово `65404` по `177530`, байт `25` по `177577` | хвост ROM, назначение не выяснено |

## Что известно о контрольных суммах

Цикл у `START` суммирует (`ADD`+`ADC`, перенос по кругу) 3 блока по 4096 слов, требуя `177777`.
Проверка по дампу:
- блок 2 (`140000`–`157777`): сумма `177777`; `SUM2` — балансирующее слово;
- блок 1 (`120000`–`137777`): сумма `177777` получилась бы с исходным `BEQ`; в ROM стоит `BR`, который
  на `1000` октал меняет сумму, поэтому в дампе она `176777`. Проверка отключена;
- блок 3 (`160000`–`177777`): ПЗУ заканчивается на `177577`, дальше адреса регистров, поэтому проверку, вероятно, отключили из-за него. Это предположение, не проверено.
- `SUM1`/`SUM2` не вычисляются сборкой, а записаны как константы из дампа. При изменении кода их пришлось бы пересчитывать.

## Не выяснено

- Почему в мёртвой «дыре» `$APPRX` (4 слова после `BR 1$`) в ROM БК-0010 стоит `360`: на работу это не влияет, вероятно остаток правки при сборке.
- Назначение слова `65404` по `177530` и байта `25` по `177577`.
- Кто и почему заменил `BEQ` на `BR` и поправил `JMP @-2(R4)`.
