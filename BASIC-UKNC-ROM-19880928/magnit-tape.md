# MAGNIT: ввод-вывод с магнитной ленты через канал 2

В ПЗУ (картридж 1988.09.28) единственный драйвер файлов — `MAGNIT` (`020534`, `DRIVER` `046252`). Он не работает с лентой сам: ЦП кладёт в ОЗУ блок параметров, сообщает его адрес процессору периферии (ПП) по каналу 2, а драйвер канала 2 в системном ПЗУ ПП (`ROM4.lst`, адреса `125030–135435`) выполняет операцию: на ленте, в картридже ПЗУ или на диске. Источники: код `MAGNIT`/`MOUT` (`IO.MAC`, `basic-rom.dis.lst`) и аннотированные листинги ПЗУ УКНЦ (`D:\Work\MyProjects-old\svn-ukncbtl\docs\other\Листинги ПЗУ`, `ROM4.lst`, `ROM6.lst`, кодировка CP1251, не CP866).

## Сторона ЦП (Бейсик)

1. Бейсик заполняет блок `MAG` (`001252`): `+0` байт кода ошибки, `+1` функция, `+2` устройство, `+4…+23` имя файла (`NAMEW`, 8 слов), `+24` адрес буфера (`ADRW`), `+26` число слов (`LENW`), `+30…` имя, прочитанное с ленты (`NAMER`), `+50` адрес загрузки, прочитанный с ленты (`ADRR`).
2. `CAS` вызывает `CALL @WRITE` (`WRITE` = `DRIVER` = `MAGNIT`).
3. `MAGNIT`: запрет `BREAK` (`NOSTOP`), `MOUT` посылает в `MDBR` (`176676`) младший и старший байты адреса блока, затем два байта `0377` (конец передачи); каждая отправка ждёт готовности канала (бит 7 `MCSR`, `176674`). Затем ждёт бит 7 `MCSR` — конец операции ПП. После этого `STOPEN` и проверка байта `+0`: ненулевой — ошибка (`SEC`).
4. `CASERR` разбирает код ошибки (`NER.`=1, `RER.`=10 и др.). Код 1 для ленты означает «заголовок не совпал»: Бейсик печатает найденное имя (`ISVARD`) и повторяет операцию до совпадения — так `LOAD "имя"` перебирает файлы на ленте.

То же делает загрузчик ПП из меню «ЗАГРУЗКА» (`ROM6.lst`, `163774$`): блоки `0,10,2,…` (диск), `0,10,21,…` (кассета ПЗУ, как в загрузчике нашего картриджа), `0,11,11,…` (магнитофон).

## Сторона ПП (`ROM4.lst`)

`125030$` читает тип устройства из байта `+2` блока: `тип = байт >> 3`; `0` — дисковод (`131176$`), `1` — магнитофон (`126236$`), `2` — кассета ПЗУ (`125162$`), `3` — ОЗУ ПП (`125644$`). BASIC использует `011` (магнитофон, номер 1).

Функции магнитофона (байт `+1` блока, номера восьмеричные; таблица `126502$`):

| Код | Подпрограмма ПП | Операторы Бейсика |
| --- | --- | --- |
| `01` | `126554$` — одинарная плотность записи | не используется Бейсиком (по коду) |
| `02` | `126632$` — двойная плотность | не используется Бейсиком (по коду) |
| `10` (`RD.`) | `127102$` — чтение файла с проверкой заголовка | `LOAD`, `CLOAD`, `MERGE`, `BLOAD` |
| `11` | `127110$` — чтение файла без проверки заголовка | по таблице; в коде Бейсика не найдено |
| `14` (`FR.`) | `127116$` — «фиктивное» чтение с заголовком (данные не пишутся в ОЗУ) | `FILES` |
| `15` | `127132$` — фиктивное чтение без проверки заголовка | по таблице |
| `16` | `127044$` — чтение блока данных | в найденных местах кода Бейсика не используется |
| `20` (`WR.`) | `126714$` — запись файла с заголовком | `SAVE`, `CSAVE`, `BSAVE` |
| `21` | `126662$` — запись блока данных | в найденных местах кода Бейсика не используется |

Остальные коды дают ответ `10` (неверная функция). Коды возврата в байт `+0`: `0` — нормально, `1` — заголовок не совпал, `12` — не совпала контрольная сумма, `10` — неверная функция (`2` — ошибка блока параметров для кассеты ПЗУ).

## Формат записи на ленте (по подпрограммам ПП)

Пилот-тон (последовательность бит «1»), заголовок — имя файла из 8 слов; для типа «УКНЦ» затем слово длины и слово адреса загрузки; пилот-тон перед данными; данные словами; контрольная сумма слов со сложением с переносом (`ADD`/`ADC`); концевой бит «1». Байт записывается как бит «0», 8 информационных бит, два бита «1». Длительности бит «1»/«0» задаются таймером: одинарная плотность `0320`/`0150`, двойная `0150`/`064`. Параметр «тип устройства» (бит 0 `R1` при чтении заголовка) в коде ПП помечен как «MSX» (бит=0) или «УКНЦ» (бит=1): ПЗУ ПП читает и ленты в стиле MSX.

## Особенности `FILES`

Перед вызовом `MAGNIT` подменяет первые три слова имени «любым» значением `0401*352` (запоминая прежние шесть байт на `+12` выше) и вызывает функцию `14`: лента читается «вхолостую», ПП возвращает имя найденного заголовка в `NAMER` (`+30`), Бейсик его печатает.

## Что не проверено

- Назначение битов `R1` при чтении заголовка и точный состав заголовка (длина, поля) — по листингам ПП, не на эмуляторе.
- Как `LOAD`/`SAVE` текстовых файлов (`CASCII`/`COPOUT`) складывают данные в блоки по `200` слов — не прослеживал.
- Работа с реальной лентой или её эмуляцией не проверялась.
